数字通信基础与分层

“UART 协议”和“Modbus 协议”根本不在一个层次。先把接口、电气、链路和应用分开，后面才不会混。

学完这一讲，你能

  • 区分接口、物理层、数据链路与应用协议
  • 解释同步/异步、单端/差分、单工/半双工/全双工
  • 从波形读出比特率与采样点
  • 判断一个通信问题该从哪一层查

1.1“协议”这个词被用得太宽了

有人说“我用 UART 协议”，有人说“我用 Modbus 协议”，还有人说“RS-485 协议”。这三句话里的“协议”根本不在一个层次：

四个层次，各管一件事
层次管什么例子典型问题
接口 / 连接器几根线、什么电平、什么接头TTL 串口、RS-232 DB9、RS-485 A/B、RJ45接反、共地、电平不匹配
物理层 / 时序0/1 怎么表示，什么时候采样UART 波特率、I²C 开漏、SPI 时钟极性波特率误差、采样点错、上升沿太慢
数据链路帧边界、地址、仲裁、校验、重传UART 帧、I²C 地址+ACK、CAN 仲裁、CRC丢字节、NACK、仲裁失败、CRC 错
应用协议这些字节是什么意思Modbus RTU、自定义命令、AT 指令功能码错、长度错、状态机错
易错

“RS-485 协议”这个说法不准确。RS-485 只规定电气特性（差分、半双工、共模范围），不规定帧格式、地址和校验。跑在 RS-485 上的应用协议可以是 Modbus RTU，也可以是自定义协议。同理，UART 只规定“怎么把字节变成电平”，不规定“字节是什么意思”。

1.2同步与异步：时钟从哪来

异步

没有时钟线，靠约定

UART、RS-485。收发双方各自用自己的时钟，靠起始位对齐，靠波特率保持同步。误差会累积。

同步

有时钟线，靠边沿

I²C、SPI。主机提供时钟，从机在指定边沿采样。没有累积误差，但多一根线。

CAN 介于两者之间：它用位填充（bit stuffing）让接收方能从数据流里恢复时钟，属于“自同步”的串行总线。

1.3单端与差分：抗干扰的两种思路

单端差分
信号一根线对地两根线之间的电压差
例子TTL UART、I²C、SPIRS-485、CAN、USB、以太网
抗干扰较弱，地电位差会影响较强，共模干扰相互抵消
距离短（板内、几十厘米）长（几十米到上千米）

差分不是“两根线各传一个信号”，而是用两根线的电压差表示 0/1。干扰通常同时叠加在两根线上（共模），相减后被抵消。

1.4单工、半双工、全双工

模式能否同时收发例子
单工只能一个方向传感器单向输出、红外发射
半双工不能同时RS-485、CAN、I²C
全双工可以同时UART（TX/RX 分开）、SPI（MOSI/MISO）

半双工需要“方向控制”：发送时驱动总线，接收时释放总线。RS-485 的 DE/RE 引脚就是干这个的；切换时机不对，会把最后一两个字节截掉。

1.5从波形读出三个参数

看一条数字波形，至少能读出三样东西：

电平标准　3.3 V TTL？5 V？差分？空闲是高还是低？
比特率　一个比特占多长时间。UART 还要看起始位和停止位。
采样点　接收方在比特的哪个位置采样（通常是中间）。
速率计算示例text
UART：115200 bps，8N1
一帧 = 1 起始 + 8 数据 + 0 校验 + 1 停止 = 10 位
一帧时间 = 10 / 115200 ≈ 86.8 µs
每秒最多约 11520 字节（理论值，不含间隔）

I²C：400 kHz，7 位地址，读写 1 字节
START + 地址(8) + ACK + 数据(8) + ACK + STOP ≈ 20 个时钟
一字节时间 ≈ 20 / 400k = 50 µs（不含软件开销）
标准怎么说

“波特率”（baud）严格指每秒符号数，不是每秒比特数。UART 每个符号只携带 1 bit，所以两者相等；但在某些调制方式下，一个符号可以携带多个比特。日常说“串口波特率 115200”时，指的是比特率。

UART：没有时钟线怎么对齐

UART 只靠约定的波特率采样。起始位、数据位、校验位、停止位各自解决什么问题？误差多大就会错？

学完这一讲，你能

  • 画出 8N1 帧并计算一帧时间
  • 解释波特率误差的累积与采样点
  • 正确配置数据位、校验与停止位
  • 区分 TTL、RS-232 与 RS-485 的电平

2.1UART 的一帧长什么样

UART 没有时钟线，收发双方靠起始位对齐，然后按约定的波特率逐位采样。空闲时线保持高电平，第一个下降沿就是起始位。

动手看

UART 帧配置器

改波特率、数据位、校验和停止位，看帧结构、总位数、单帧时间和理论吞吐如何变化。

“8N1”表示 8 数据位、无校验、1 停止位。两边配置必须完全一致，否则会解析出乱码或帧错误。

2.2波特率误差：为什么 115200 会乱码

接收方没有时钟线，只能按自己的波特率估算每一位的位置。如果双方时钟有偏差，采样点会逐渐偏离位中心，到第 9、10 位就可能采错。

总误差后果
< 1%安全，绝大多数场景没问题
1% – 2%通常可用，但接近边界；长帧/高温/低精度晶振要小心
2% – 3%偶发帧错误，表现为“大部分正常，偶尔乱码”
> 3%基本不可用，成片乱码

误差来源：晶振精度（RC 振荡器可能 ±2%）、波特率分频取整、温度漂移。用内部 RC 振荡器跑高波特率，是最常见的翻车原因。

工程习惯

高波特率（≥ 460800）优先用外部晶振；如果必须用内部 RC，先把波特率降下来，或者留出校准机制。计算分频时看实际误差，不要只看“接近”。

2.3校验位：能查错，不能纠错

配置校验位能发现不能发现
无（N）——任何位错误
偶（E）使 1 的个数为偶数奇数个位翻转偶数个位翻转
奇（O）使 1 的个数为奇数奇数个位翻转偶数个位翻转

校验位只能告诉你“这一帧可能错了”，不能纠正，也不能保证一定对。真正的数据完整性要靠应用层的 CRC。

TTL 串口RS-232RS-485
电平0 / 3.3 V 或 5 V±3 – ±15 V，逻辑反相差分 A/B
距离板内几十厘米十几米几十米到 1200 米
拓扑点对点点对点多点总线
典型芯片MCU 引脚直连MAX3232MAX485 / SP3485
易错

把 TTL 串口直接接到 RS-232 的 DB9 上，可能因负电压损坏引脚；把 RS-485 的 A/B 接反，表现为“完全收不到数据”，但波形其实存在。接线前先确认电平标准和引脚定义。

UART 接收：中断、缓冲与 DMA

中断里收字节只是开始。环形缓冲区、空闲中断、DMA 和帧解析，才决定高波特率下会不会丢数据。

学完这一讲，你能

  • 设计中断 + 环形缓冲的接收路径
  • 用空闲中断/DMA 处理不定长帧
  • 避免中断里做耗时处理
  • 统计溢出与帧错误

3.1为什么轮询接收会丢数据

UART 接收寄存器通常只能存 1 个字节。如果 CPU 正在处理别的事，第二个字节到达时，第一个还没被读走，就会溢出（overrun）。标志位会告诉你“丢了一个字节”，但数据已经没了。

波特率一个字节时间主循环能耽误多久
9600≈ 1.04 ms约 1 ms
115200≈ 86.8 µs不到 0.1 ms
921600≈ 10.9 µs几乎不能耽误

所以高速/连续接收必须用中断或 DMA，把“搬运”与“处理”分开。

3.2中断 + 环形缓冲区

uart_rx.c · 平台相关（伪寄存器名）C11
#include <stdint.h>
#include <stdbool.h>

#define RX_CAP 128

static volatile uint8_t  g_rx[RX_CAP];
static volatile uint16_t g_head, g_tail;
static volatile uint32_t g_overrun;

void USART1_IRQHandler(void)
{
    uint32_t sr = UART_SR;

    if (sr & UART_SR_ORE) {
        g_overrun++;                  /* 记录溢出，读 DR 清标志 */
    }
    if (sr & UART_SR_RXNE) {
        uint8_t byte = (uint8_t)UART_DR;
        uint16_t next = (uint16_t)((g_head + 1u) % RX_CAP);
        if (next != g_tail) {
            g_rx[g_head] = byte;
            g_head = next;
        } else {
            g_overrun++;              /* 缓冲区满：丢弃并计数 */
        }
    }
}

/* 主循环：取出所有已到达的字节 */
bool rx_pop(uint8_t *out)
{
    if (g_head == g_tail) {
        return false;
    }
    *out = g_rx[g_tail];
    g_tail = (uint16_t)((g_tail + 1u) % RX_CAP);
    return true;
}
先修回顾

环形缓冲区就是一块固定数组加两个索引：head 由写入方（中断）推进，tail 由读取方（主循环）推进；索引到末尾回绕到 0。写的时候先写数据再移动 head，读的时候先取数据再移动 tail，这样对方看到指针变化时数据一定已经就绪。完整实现与满/空判定见第 2 册第 10 讲。

工程习惯

中断里只做“读寄存器 + 存缓冲区 + 计数”，不做解析、不打印。解析放在主循环或任务里。这样即使一帧很长、处理很慢，中断也能及时把字节收走。

I²C：两根线挂一堆设备

I²C 用开漏输出和上拉电阻实现“线与”，用地址选中设备，用 ACK 确认每个字节。

4.1两根线，怎么挂一堆设备

I²C 只用两根线：SCL（时钟）和 SDA（数据）。所有设备都把它们接成开漏输出，外加上拉电阻。任何设备只能把线拉低，不能主动拉高——高电平由上拉电阻恢复。

实现细节

开漏 + 上拉构成“线与”：只要有一个设备拉低，总线就是低；所有设备都释放，总线才是高。这让多个设备可以共享总线而不短路，也实现了 ACK 和仲裁。

4.2一次完整的读操作

START　主机拉低 SDA（SCL 高）。
发送地址 + 读位　7 位地址左移一位，最低位 1 表示读。
等待 ACK　从机拉低 SDA 表示“我在”。
接收数据　从机发 8 位，主机回 ACK（还要继续读）或 NACK（读完了）。
STOP　主机在 SCL 高时释放 SDA（上升沿）。
i2c_read.c · 平台相关（伪 API）C11
#include <stdint.h>
#include <stdbool.h>

/* 读寄存器：典型传感器操作 */
bool i2c_read_reg(uint8_t addr7, uint8_t reg, uint8_t *out)
{
    uint8_t a8 = (uint8_t)(addr7 << 1);        /* 写 */
    if (!i2c_start()) return false;
    if (!i2c_write(a8))   { i2c_stop(); return false; }   /* 地址 NACK */
    if (!i2c_write(reg))  { i2c_stop(); return false; }   /* 寄存器号 NACK */

    /* 重复起始：不发 STOP，直接换方向 */
    if (!i2c_start()) return false;
    if (!i2c_write((uint8_t)(a8 | 1u))) { i2c_stop(); return false; }

    *out = i2c_read_nack();                    /* 只读 1 字节：回 NACK */
    i2c_stop();
    return true;
}
易错

读最后一个字节时必须回 NACK，告诉从机“不要再发了”。如果回 ACK，从机会继续输出，主机却已经发 STOP，时序就乱了。很多“读出来总是多一字节/错位”的问题都出在这里。

/* 总线恢复：从机可能卡在“等第 9 个时钟”，手动补时钟让它释放 SDA */
void i2c_bus_recover(void)
{
    gpio_set_scl_input();          /* 先释放 SCL */
    for (int i = 0; i < 9; i++) {
        gpio_scl_low();  delay_us(5);
        gpio_scl_high(); delay_us(5);
    }
    /* 手动产生 STOP：SCL 高时 SDA 由低变高 */
    gpio_sda_low();  delay_us(5);
    gpio_scl_high(); delay_us(5);
    gpio_sda_high(); delay_us(5);
}

上拉太小：功耗高、低电平灌电流大；上拉太大：上升沿变慢，高速时来不及拉高。经验起点：100 kHz 用 4.7 kΩ，400 kHz 用 2.2 kΩ，具体要按总线电容和器件规格计算。

工程习惯

示波器看 I²C 波形时，重点看上升沿是否“圆角”、高电平是否达到 Vih。上升沿太慢是“偶发 NACK/错位”的常见原因，尤其在长排线、多设备、高电容的板子上。

5.1四根线，全双工

/* 全双工：发一个字节的同时收一个字节 */
uint8_t spi_xfer(uint8_t out)
{
    uint8_t in = 0;
    for (int i = 7; i >= 0; i--) {          /* MSB 先发 */
        gpio_mosi((out >> i) & 1u);
        gpio_sclk(1);                        /* 模式 0：上升沿采样 */
        in = (uint8_t)((in << 1) | gpio_miso());
        gpio_sclk(0);
    }
    return in;
}

5.4多从机怎么接

独立片选

最常见

所有从机共用 SCLK/MOSI/MISO，每个从机一根独立 CS。主机同一时刻只拉低一个 CS。

菊花链

省引脚

从机的 MISO 接下一个的 MOSI，共用一根 CS。数据要移过整条链，适合移位寄存器/部分 LED 驱动。

独立片选要注意：不要同时拉低两个 CS，否则两个从机同时驱动 MISO，会打架。上电默认要把所有 CS 拉高。

5.5SPI 没有 ACK，怎么保证可靠

  • 从机的状态寄存器（读回配置、检查 busy 位）。
  • 命令回读（写完后读回比较）。
  • 应用层 CRC / 重试。
  • 关键操作加超时，避免死等 busy。

6.1CAN 用“消息”而不是“地址”

CAN 总线上没有从机地址。每个报文带一个标识符，既表示“这是什么消息”，也表示“优先级”。所有节点都收到，靠验收滤波器决定要不要处理。

6.2仲裁：为什么冲突不会丢数据

CAN 的 0 是显性（dominant），1 是隐性（recessive）。多个节点同时发送时，总线呈现“显性与”——只要有一个节点发 0，总线就是 0。

节点每发一位都会回读总线：如果自己发 1 却读到 0，说明有更高优先级的节点在发，于是立刻退出仲裁，转为接收。输家不会破坏赢家的数据，这叫非破坏性仲裁。

动手看

三位选手，逐位仲裁

仲裁只在总线空闲时发生；一旦开始发送，其他节点必须等总线空闲才能尝试。错误帧会打断当前传输。

一个位时间被分成同步段、传播段、相位段 1/2。采样点通常在 75%–87.5% 处。所有节点的波特率和采样点必须一致，否则会出现间歇性错误。

RS-485 规定的是差分电平、共模范围、多点总线，不规定帧格式、地址和校验。它经常和 Modbus RTU 一起出现，所以很多人误以为它们是同一个东西。

7.2半双工与方向控制

RS-485 收发器通常有 DE（驱动使能）和 /RE（接收使能）两个引脚，常接在一起用一个 GPIO 控制：高电平发送，低电平接收。

rs485_send.c · 平台相关C11
void rs485_send(const uint8_t *buf, size_t len)
{
    gpio_de(1);                     /* 切到发送 */
    delay_us(10);                   /* 等收发器稳定（按器件手册） */

    for (size_t i = 0; i < len; i++) {
        uart_putc(buf[i]);
    }

    uart_wait_tx_complete();        /* 等最后一个字节真正移出，不能只看 DR 空 */
    delay_us(10);
    gpio_de(0);                     /* 释放总线，切回接收 */
}
实现细节

TXE（发送寄存器空）只表示“可以写下一个字节”，不表示“最后一个字节已经发完”。要等 TC（传输完成），否则提前切回接收会把最后一个字节的尾部截掉。

7.4CRC16：算错就永远不通

Modbus RTU 用的是 CRC-16/MODBUS：多项式 0x8005 的反射形式 0xA001，初值 0xFFFF，不反转输入输出，不做最终异或。发送时低字节在前。

modbus_crc.cC11
#include <stdint.h>
#include <stddef.h>

uint16_t modbus_crc16(const uint8_t *data, size_t len)
{
    uint16_t crc = 0xFFFFu;
    for (size_t i = 0; i < len; i++) {
        crc ^= data[i];
        for (int b = 0; b < 8; b++) {
            if (crc & 1u) {
                crc = (uint16_t)((crc >> 1) ^ 0xA001u);
            } else {
                crc >>= 1;
            }
        }
    }
    return crc;
}

自定义二进制协议

当现成协议不够用，就要自己设计帧。长度字段、转义、CRC 和重同步，每一项都决定协议的健壮性。

8.1什么时候需要自定义协议

现成协议不够用时才自己设计：字段特殊、开销要求高、需要多路复用、需要版本演进。设计目标通常只有三个：能分帧、能检错、能扩展。

设计项常见选择取舍

长度1–2 字节，表示载荷长度必须有上限，解析前先校验
类型/命令1 字节区分请求/响应/事件
序号1 字节，请求响应配对支持重传与乱序检测
校验CRC16 / CRC32 / 简单和CRC 检错强，计算稍贵
转义字节填充（如 0x7D）避免载荷中出现帧头，但增加复杂度

8.2一个可用的帧格式

帧格式定义text
+--------+--------+--------+--------+--------+---------+--------+--------+
| 0xAA   | 0x55   | type   | seq    | len    | payload | crc_lo | crc_hi |
+--------+--------+--------+--------+--------+---------+--------+--------+
  帧头     帧头     类型     序号     长度     len 字节   CRC16（低字节先发）

type: 0x01 读请求  0x02 写请求  0x81 读响应  0x82 写响应  0xFF 错误

crc : 对 type..payload 计算，多项式 0x8005 反射（0xA001），初值 0xFFFF
易错

长度字段是解析器最容易被攻击的地方。如果直接 memcpy(dst, payload, len) 而不检查 len <= sizeof dst，一个错误的长度字节就能造成缓冲区溢出。所有来自外部的长度都必须先校验。

8.3解析状态机

frame_parser.cC11
#include <stdint.h>
#include <stdbool.h>
#include <string.h>
#include <stddef.h>

#define SOF1        0xAAu
#define SOF2        0x55u
#define MAX_PAYLOAD 32u

typedef enum {
    ST_SOF1 = 0, ST_SOF2, ST_TYPE, ST_SEQ, ST_LEN, ST_PAYLOAD, ST_CRC_LO, ST_CRC_HI
} pstate_t;

/* CRC-16/MODBUS：覆盖 type、seq、len 与 payload */
static uint16_t crc16_frame(uint8_t type, uint8_t seq, uint8_t len, const uint8_t *p)
{
    uint8_t buf[MAX_PAYLOAD + 3];
    buf[0] = type; buf[1] = seq; buf[2] = len;
    memcpy(&buf[3], p, len);

    uint16_t crc = 0xFFFFu;
    for (size_t i = 0; i < (size_t)len + 3u; i++) {
        crc ^= buf[i];
        for (int b = 0; b < 8; b++) {
            crc = (crc & 1u) ? (uint16_t)((crc >> 1) ^ 0xA001u) : (uint16_t)(crc >> 1);
        }
    }
    return crc;
}

typedef struct {
    pstate_t state;
    uint8_t  type, seq, len, index;
    uint8_t  payload[MAX_PAYLOAD];
    uint16_t crc_rx;
} parser_t;

/* out 缓冲区由调用者提供，长度至少为 MAX_PAYLOAD；
   返回 true 表示收到一个完整且校验通过的帧 */
bool parser_feed(parser_t *p, uint8_t b, uint8_t *type, uint8_t *seq,
                 uint8_t *payload, uint8_t *len)
{
    switch (p->state) {
    case ST_SOF1:
        if (b == SOF1) p->state = ST_SOF2;
        break;
    case ST_SOF2:
        p->state = (b == SOF2) ? ST_TYPE : (b == SOF1 ? ST_SOF2 : ST_SOF1);
        break;
    case ST_TYPE:
        p->type = b; p->state = ST_SEQ;
        break;
    case ST_SEQ:
        p->seq = b; p->state = ST_LEN;
        break;
    case ST_LEN:
        if (b > MAX_PAYLOAD) { p->state = ST_SOF1; break; }   /* 非法长度：重同步 */
        p->len = b; p->index = 0;
        p->state = (b == 0) ? ST_CRC_LO : ST_PAYLOAD;
        break;
    case ST_PAYLOAD:
        p->payload[p->index++] = b;
        if (p->index >= p->len) p->state = ST_CRC_LO;
        break;
    case ST_CRC_LO:
        p->crc_rx = b; p->state = ST_CRC_HI;
        break;
    case ST_CRC_HI:
        p->crc_rx |= (uint16_t)(b << 8);
        p->state = ST_SOF1;
        if (crc16_frame(p->type, p->seq, p->len, p->payload) == p->crc_rx) {
            *type = p->type; *seq = p->seq; *len = p->len;
            memcpy(payload, p->payload, p->len);
            return true;
        }
        break;
    default:
        p->state = ST_SOF1;
        break;
    }
    return false;
}

8.4粘包、半包与重同步

粘包

一次收到 [帧1][帧2]。解析器必须循环喂字节，直到没有剩余，而不是“一次调用解一帧”。

半包

只收到半帧。状态机必须保存中间状态，下次继续；不能要求“每次喂一整帧”。

噪声

帧头前有乱码。状态机要能在任意位置重新找到 AA 55，而不是一直错位。

最稳妥的测试方法是：把一帧拆成任意长度的片段，逐个喂给解析器，结果必须一致；再在前后插入随机字节，解析器必须能恢复。

8.5版本与扩展

  • 帧里留 1 字节版本号，或者用 type 的高位表示版本。
  • 新增字段时，优先“追加在末尾 + 用长度判断”，不要改变已有字段的偏移。
  • 未知 type 要能安全忽略，而不是崩溃。
  • 保留字段写 0，读取时忽略。
工程习惯

协议一旦发布就很难改。设计时多留 1 字节版本、多留几个保留位，比事后“加个字段导致所有设备不兼容”便宜得多。

软件逻辑分析仪看到正确数据，MCU 却处理错缓冲区、状态机、中断优先级、并发

这四类的顺序不能反：电气不通，谈时序没意义；时序不对，协议解析必然错；协议对了但软件错，才是代码问题。

9.5一个可复用的排障脚本

  1. 用万用表确认供电和地。
  2. 用示波器确认空闲电平（UART 应为高，I²C 应为高，CAN 隐性）。
  3. 让设备周期性发送固定字节（如 0x55），用逻辑分析仪看波形是否规整。
  4. 解码，确认波特率/模式与代码一致。
  5. 换成真实数据，逐字节比对发送与接收。
  6. 加上 CRC/长度检查，确认错误是“偶发”还是“必现”。
  7. 偶发问题再查终端、共地、电源纹波、中断延迟。
易错

“换一根线就好了”不代表问题解决。线材问题往往掩盖了终端缺失、驱动能力不足或地回路问题；换线后要复测波形，确认不是暂时压住了症状。

10.2接口：proto.h

proto.hC11
#ifndef PROTO_H
#define PROTO_H

#include <stdint.h>
#include <stddef.h>

#define PROTO_SOF1     0xAAu
#define PROTO_SOF2     0x55u
#define PROTO_MAX_PAYLOAD 32u

typedef enum {
    PROTO_OK = 0,
    PROTO_ERR_TYPE,
    PROTO_ERR_RANGE,
    PROTO_ERR_LEN,
    PROTO_ERR_CRC
} proto_status_t;

typedef enum {
    TYPE_GET_REQ = 0x01,
    TYPE_SET_REQ = 0x02,
    TYPE_GET_RSP = 0x81,
    TYPE_SET_RSP = 0x82,
    TYPE_ERROR   = 0xFF
} proto_type_t;

typedef struct {
    uint8_t state;
    uint8_t type, seq, len, index;
    uint8_t payload[PROTO_MAX_PAYLOAD];
    uint16_t crc_rx;
} proto_parser_t;

void proto_init(proto_parser_t *p);

/* 喂一个字节；返回 1 表示收到完整帧（已通过 CRC） */
int proto_feed(proto_parser_t *p, uint8_t byte);

/* 处理一帧，生成响应帧到 out；返回响应长度，0 表示不响应 */
size_t proto_handle(const proto_parser_t *p, uint8_t *out, size_t out_len);

const char *proto_status_str(proto_status_t st);

#endif

三个关键约定：

  • proto_feed 返回 1 表示“收到完整且 CRC 正确的帧”；返回负数表示“检测到错误并已重同步”。
  • 解析器只保存状态，不分配内存；payload 固定 32 字节。
  • proto_handle 只依赖解析结果，不依赖硬件。

10.3实现：proto.c

proto.cC11
#include "proto.h"

#include <string.h>

enum { S_SOF1 = 0, S_SOF2, S_TYPE, S_SEQ, S_LEN, S_PAYLOAD, S_CRC_LO, S_CRC_HI };

static uint16_t crc16(const uint8_t *d, size_t n)
{
    uint16_t crc = 0xFFFFu;
    for (size_t i = 0; i < n; i++) {
        crc ^= d[i];
        for (int b = 0; b < 8; b++) {
            crc = (crc & 1u) ? (uint16_t)((crc >> 1) ^ 0xA001u) : (uint16_t)(crc >> 1);
        }
    }
    return crc;
}

static uint16_t frame_crc(uint8_t type, uint8_t seq, uint8_t len, const uint8_t *payload)
{
    uint8_t buf[PROTO_MAX_PAYLOAD + 3u];
    buf[0] = type;
    buf[1] = seq;
    buf[2] = len;
    if (len > 0u) {
        memcpy(&buf[3], payload, len);
    }
    return crc16(buf, (size_t)len + 3u);
}

void proto_init(proto_parser_t *p)
{
    memset(p, 0, sizeof *p);
    p->state = S_SOF1;
}

int proto_feed(proto_parser_t *p, uint8_t b)
{
    switch (p->state) {
    case S_SOF1:
        if (b == PROTO_SOF1) p->state = S_SOF2;
        break;
    case S_SOF2:
        if (b == PROTO_SOF2) p->state = S_TYPE;
        else if (b != PROTO_SOF1) p->state = S_SOF1;
        break;
    case S_TYPE:
        p->type = b;
        p->state = S_SEQ;
        break;
    case S_SEQ:
        p->seq = b;
        p->state = S_LEN;
        break;
    case S_LEN:
        if (b > PROTO_MAX_PAYLOAD) {
            p->state = S_SOF1;              /* 非法长度：重同步 */
            return -1;
        }
        p->len = b;
        p->index = 0;
        p->state = (b == 0u) ? S_CRC_LO : S_PAYLOAD;
        break;
    case S_PAYLOAD:
        p->payload[p->index++] = b;
        if (p->index >= p->len) p->state = S_CRC_LO;
        break;
    case S_CRC_LO:
        p->crc_rx = b;
        p->state = S_CRC_HI;
        break;
    case S_CRC_HI:
        p->crc_rx |= (uint16_t)((uint16_t)b << 8);
        p->state = S_SOF1;
        if (frame_crc(p->type, p->seq, p->len, p->payload) == p->crc_rx) {
            return 1;
        }
        return -2;                          /* CRC 错 */
    default:
        p->state = S_SOF1;
        break;
    }
    return 0;
}

static size_t build(uint8_t type, uint8_t seq, const uint8_t *payload, uint8_t len,
                    uint8_t *out, size_t out_len)
{
    size_t need = (size_t)len + 7u;         /* 2 SOF + type + seq + len + payload + 2 CRC */
    if (out_len < need) {
        return 0;
    }
    out[0] = PROTO_SOF1;
    out[1] = PROTO_SOF2;
    out[2] = type;
    out[3] = seq;
    out[4] = len;
    if (len > 0u) {
        memcpy(&out[5], payload, len);
    }
    uint16_t crc = frame_crc(type, seq, len, payload);
    out[5 + len] = (uint8_t)(crc & 0xFFu);
    out[6 + len] = (uint8_t)(crc >> 8);
    return need;
}

size_t proto_handle(const proto_parser_t *p, uint8_t *out, size_t out_len)
{
    uint8_t rsp[PROTO_MAX_PAYLOAD];

    switch (p->type) {
    case TYPE_GET_REQ:
        if (p->len != 1u || p->payload[0] > 3u) {
            rsp[0] = (uint8_t)PROTO_ERR_RANGE;
            return build(TYPE_ERROR, p->seq, rsp, 1u, out, out_len);
        }
        rsp[0] = p->payload[0];
        rsp[1] = (uint8_t)(100u + p->payload[0]);
        return build(TYPE_GET_RSP, p->seq, rsp, 2u, out, out_len);

    case TYPE_SET_REQ:
        if (p->len != 2u || p->payload[0] > 3u) {
            rsp[0] = (uint8_t)PROTO_ERR_RANGE;
            return build(TYPE_ERROR, p->seq, rsp, 1u, out, out_len);
        }
        return build(TYPE_SET_RSP, p->seq, p->payload, 2u, out, out_len);

    default:
        rsp[0] = (uint8_t)PROTO_ERR_TYPE;
        return build(TYPE_ERROR, p->seq, rsp, 1u, out, out_len);
    }
}

const char *proto_status_str(proto_status_t st)
{
    switch (st) {
    case PROTO_OK:        return "ok";
    case PROTO_ERR_TYPE:  return "unknown type";
    case PROTO_ERR_RANGE: return "out of range";
    case PROTO_ERR_LEN:   return "bad length";
    case PROTO_ERR_CRC:   return "crc error";
    default:              return "?";
    }
}
易错

frame_crc 里的临时缓冲区是 PROTO_MAX_PAYLOAD + 3，而 len 在进入状态机时已经校验过上限。如果哪天把上限改大却忘了改缓冲区，就会栈溢出——所以两处必须用同一个宏。

main.cC11
#include "proto.h"

#include <stdio.h>
#include <string.h>

static size_t make(uint8_t type, uint8_t seq, const uint8_t *pl, uint8_t len, uint8_t *out)
{
    size_t n = (size_t)len + 7u;
    out[0] = PROTO_SOF1; out[1] = PROTO_SOF2; out[2] = type; out[3] = seq; out[4] = len;
    if (len) memcpy(&out[5], pl, len);

    uint8_t buf[PROTO_MAX_PAYLOAD + 3u];
    buf[0] = type; buf[1] = seq; buf[2] = len;
    if (len) memcpy(&buf[3], pl, len);

    uint16_t crc = 0xFFFFu;
    for (size_t i = 0; i < (size_t)len + 3u; i++) {
        crc ^= buf[i];
        for (int b = 0; b < 8; b++)
            crc = (crc & 1u) ? (uint16_t)((crc >> 1) ^ 0xA001u) : (uint16_t)(crc >> 1);
    }
    out[5 + len] = (uint8_t)(crc & 0xFFu);
    out[6 + len] = (uint8_t)(crc >> 8);
    return n;
}

static void dump(const char *tag, const uint8_t *p, size_t n)
{
    printf("%-22s", tag);
    for (size_t i = 0; i < n; i++) printf("%02X ", p[i]);
    printf("\n");
}

int main(void)
{
    proto_parser_t ps;
    proto_init(&ps);

    uint8_t frame[64], rsp[64];
    uint8_t pl[4] = { 2, 55 };

    size_t n = make(TYPE_GET_REQ, 7, pl, 1, frame);
    dump("GET ch2", frame, n);

    /* 逐字节喂入，模拟分片到达 */
    for (size_t i = 0; i < n; i++) {
        int r = proto_feed(&ps, frame[i]);
        if (r == 1) {
            size_t rn = proto_handle(&ps, rsp, sizeof rsp);
            dump("  -> response", rsp, rn);
        }
    }

    /* 噪声 + 一帧写请求 */
    uint8_t noise[] = { 0x00, 0xAA, 0x00, 0xAA, 0x00 };
    for (size_t i = 0; i < sizeof noise; i++) (void)proto_feed(&ps, noise[i]);
    n = make(TYPE_SET_REQ, 8, pl, 2, frame);
    for (size_t i = 0; i < n; i++) {
        if (proto_feed(&ps, frame[i]) == 1) {
            size_t rn = proto_handle(&ps, rsp, sizeof rsp);
            dump("SET ch2=55", rsp, rn);
        }
    }

    /* 破坏 CRC */
    n = make(TYPE_GET_REQ, 9, pl, 1, frame);
    frame[n - 1] ^= 0xFF;
    int last = 0;
    for (size_t i = 0; i < n; i++) last = proto_feed(&ps, frame[i]);
    printf("bad crc                feed returned %d (%s)\n", last,
           last == -2 ? "crc error" : "other");

    /* 非法长度：0x40 > 32 */
    uint8_t bad_len[] = { PROTO_SOF1, PROTO_SOF2, 0x01, 0x0A, 0x40, 0x00 };
    last = 0;
    for (size_t i = 0; i < sizeof bad_len; i++) {
        last = proto_feed(&ps, bad_len[i]);
        if (last < 0) break;
    }
    printf("bad length             feed returned %d (%s)\n", last,
           last == -1 ? "resync" : "other");
    return 0;
}

{
    int r = proto_feed(&g_parser, b);
    if (r == 1) {
        uint8_t rsp[64];

        if (n > 0) {

参考答案与思路

A.6设计检查清单

  • 物理层：电平、上拉/终端、共地、走线长度都确认过
  • 时序：波特率误差、采样点、建立/保持时间在规格内
  • 分帧：长度字段有上限校验，帧头不会与载荷冲突
  • 校验：CRC 参数（初值/反转/异或/字节序）与对端一致
  • 错误：CRC 错、长度错、超时、NACK 都有明确处理
  • 并发：中断与主循环共享数据有保护
  • 测试：分片、粘包、噪声、边界、长时间运行都跑过
  • 调试：板上留了测试点、日志和错误计数
