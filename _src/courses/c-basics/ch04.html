4.1if 的本质：只关心“是不是 0”

C 没有真正的布尔类型（C99 的 _Bool 是后来补的）。条件表达式的规则只有一条：结果为 0 就是假，非 0 就是真。所以 if (1)、if (42)、if ('a') 都成立。

#include int main(void) { int score = 0; if (scanf("%d", &score) != 1) { /* scanf 返回成功读入的项数 */ printf("输入不是整数\n"); return 1; } if (score >= 90) { printf("A\n"); } else if (score >= 80) { printf("B\n"); } else if (score >= 60) { printf("C\n"); } else { printf("D\n"); } return 0; } B
易错

悬空 else：else 总是和最近的、尚未配对的 if 结合。下面这段代码的本意是“x 大于 0 且 y 大于 0 才打印”，实际却变成了“x 大于 0 时，如果 y 不大于 0 就打印”。加花括号是唯一可靠的解决办法。

if (x > 0) if (y > 0) printf("both positive\n"); else printf("x <= 0\n"); /* 这个 else 属于内层 if！ */

4.2switch：适合“一个值，多种情况”

switch 的括号里必须是整数类型（包括 char、枚举），case 后面必须是编译期常量。它比一长串 else if 更清楚，也更容易让编译器生成跳转表。

#include int main(void) { int cmd = 2; switch (cmd) { case 1: printf("read\n"); break; case 2: case 3: /* 2 和 3 共用一段处理：故意穿透 */ printf("write\n"); break; default: printf("unknown\n"); break; } return 0; } write
  • 穿透（fallthrough）是特性不是 bug：没有 break 就会继续执行下一个 case。共用逻辑时刻意利用它，其他情况一定写 break。
  • default 不是必需的，但建议写。它能让“漏了某种情况”变得可见。
  • 在 case 里定义变量要加花括号，否则可能跳过初始化，编译器会报 jump to case label crosses initialization。

4.3三种循环，各有各的场合

写法什么时候用注意
for (初始化; 条件; 步进)次数已知，或有一目了然的计数器三段都可省略，但别写出 for(;;) 却忘了 break
while (条件)次数未知，先判断再执行循环体可能一次都不执行
do { } while (条件);至少执行一次，例如“先读一次再判断”注意结尾的分号
#include int main(void) { int sum = 0; for (int i = 0; i < 5; i++) { sum += i; } printf("sum=%d\n", sum); /* 0+1+2+3+4 = 10 */ int n = 0; while (n < 3) { printf("while %d\n", n); n++; } int tries = 0; do { printf("do-while %d\n", tries); tries++; } while (tries < 2); return 0; } sum=10 while 0 while 1 while 2 do-while 0 do-while 1
动手看

for 循环到底执行了几次

把循环拆成“初始化 → 判断 → 循环体 → 步进”四步，单步走一遍。重点看条件在什么时候变成假。

循环执行 n 次，但条件判断执行了 n+1 次——最后一次判断为假，循环才结束。

4.4break、continue 与 goto

  • break：立刻跳出最内层的 switch 或循环。
  • continue：跳过本次循环剩余部分，直接进入下一次的条件判断（for 会先执行步进）。
  • goto：无条件跳转（可以向前也可以向后）。现代代码里几乎只有一个合理用途——从多层嵌套中统一跳到错误处理标签。
#include int work(void) { int ret = -1; char *buf = malloc(256); if (buf == NULL) { goto out; /* 没分配成功，直接返回 */ } if (init_device() != 0) { goto out_free; } ret = 0; out_free: free(buf); out: return ret; }
工程习惯

这种“单入口、单出口、集中清理”的写法在 C 项目里很常见（Linux 内核大量使用）。它比在每个失败分支里重复 free 更不容易漏。但不要用 goto 往回跳，那会把控制流变成一团乱麻。

4.5边界：循环最容易错的地方

/* 错误 1：多跑一次，访问 data[10] 越界 */ for (int i = 0; i <= 10; i++) { sum += data[i]; } /* 错误 2：少跑一次，最后一个元素没处理 */ for (int i = 0; i < 10 - 1; i++) { sum += data[i]; } /* 错误 3：无符号倒序，i >= 0 永远成立 */ for (unsigned int i = 10; i >= 0; i--) { } /* 错误 4：浮点计数器累积误差 */ for (double d = 0.0; d != 1.0; d += 0.1) { } /* 可能永远不结束 */ /* 正确：用整数计数，用 < 上界 */ for (int i = 0; i < 10; i++) { sum += data[i]; }
正确做法

写循环前先问三个问题：第一次处理哪个元素？最后一次处理哪个？空集合时会不会出错？把这三个边界想清楚，比事后调试快得多。

动手练习 · 第 4 讲
  1. 写程序打印 1–100 中所有能被 3 或 5 整除的数，每行 5 个。
  2. 用 switch 实现一个简单计算器：输入两个数和运算符，输出结果，处理除零。
  3. 下面的循环输出什么？for (int i = 0; i < 5; i++) { if (i == 2) continue; printf("%d", i); }
  4. 把 4.5 节的四个错误逐一改对，并说明每个错误的后果。
参考答案与思路

1. 用 for (int i = 1; i <= 100; i++) 判断 i % 3 == 0 || i % 5 == 0，用一个计数器控制每输出 5 个换行。

2. 注意 switch 只能对整数做分支，所以先读运算符字符，再在 case '+' 里计算；除法前判断除数是否为 0。

3. 输出 0134。continue 跳过了 printf，但 i++ 仍会执行。

4. 错误 1 越界读；错误 2 漏掉最后一个元素；错误 3 无符号回绕导致死循环；错误 4 浮点误差导致条件永远不精确成立，应改成整数计数或 d < 1.0 加容差。

自测：for (int i = 0; i < 3; i++) 的循环体执行几次？条件判断几次？

i=0、1、2 时条件成立，各执行一次循环体；i=3 时条件为假，循环结束。所以循环体 3 次，条件判断 4 次。

本讲小结

  • 条件只看“是不是 0”，不要依赖非 0 的具体值。
  • switch 的穿透要显式控制，每个 case 想清楚要不要 break。
  • 循环选型看“次数是否已知、是否至少执行一次”。
  • 边界错误是循环的头号 bug，先想清楚首项、末项和空集合。
