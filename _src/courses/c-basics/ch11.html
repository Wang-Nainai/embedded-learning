概念回答的问题取值
作用域名字在源码的哪里可见块作用域、函数作用域、文件作用域
存储期对象在运行时活多久自动（栈）、静态（全程）、动态（malloc 到 free）

11.3malloc、calloc、realloc、free

函数作用注意
malloc(n)分配 n 字节，内容未初始化返回 void *，失败返回 NULL
calloc(n, size)分配 n×size 字节并全部清零适合数组；乘法可能溢出，需检查
realloc(p, n)把已分配块调整到 n 字节可能搬移，必须用临时指针接收
free(p)释放 malloc/calloc/realloc 得到的块free(NULL) 安全；释放别的地址是未定义行为
#include #include int main(void) { size_t n = 5; int *a = malloc(n * sizeof *a); /* 用 sizeof *a，改类型时不用改代码 */ if (a == NULL) { fprintf(stderr, "out of memory\n"); return 1; } for (size_t i = 0; i < n; i++) { a[i] = (int)(i * i); } /* 扩容到 10 个元素：一定要用临时指针 */ int *tmp = realloc(a, 10 * sizeof *a); if (tmp == NULL) { free(a); /* 原块还在，别忘了释放 */ return 1; } a = tmp; for (size_t i = n; i < 10; i++) { a[i] = 0; } printf("%d %d\n", a[3], a[9]); free(a); a = NULL; return 0; } 9 0
易错

p = realloc(p, n); 是经典错误：如果 realloc 失败返回 NULL，原来的 p 就被覆盖了，那块内存再也找不到，直接泄漏。必须用临时变量接。

11.4所有权：谁分配，谁释放

动态内存本身不难，难的是约定：这块内存归谁？什么时候释放？函数返回的指针，调用者要不要 free？如果接口文档不写清楚，泄漏和双重释放迟早出现。

模式 A

调用者提供缓冲区

函数只往里写，不分配。int format(char *out, size_t n, ...)。最安全，所有权清晰。

模式 B

函数分配，调用者释放

函数内部 malloc，返回指针；文档必须写明“用完请 free”。命名上可以用 create_ / destroy_ 成对出现。

11.5六类内存错误

错误典型代码后果
内存泄漏malloc 后忘记 free，或提前 return长时间运行后内存耗尽
悬空指针free 后继续用 p读到脏数据或崩溃
双重释放同一指针 free 两次堆管理器崩溃
越界写a[n] = 0破坏堆块头或相邻对象
释放非堆地址free(&local)未定义行为
未初始化读取malloc 后直接读得到随机值
动手看

分配、释放与悬空

按顺序操作：分配 A → 分配 B → 释放 A → 再通过 pa 写入。观察“指针还在，但内存已经不属于你”。

释放后把指针置 NULL 能防止误用；但如果有两份指针指向同一块，置空一份救不了另一份。

11.6让工具替你找内存错误

人眼很难发现越界一个字节或漏掉一次 free。把下面两个工具用起来，比打印一百次调试信息有效：

# GCC / Clang：地址检查 + 未定义行为检查（推荐日常开启） gcc -std=c11 -g -fsanitize=address,undefined dynamic.c -o dynamic ./dynamic # Valgrind（Linux / macOS，需单独安装） valgrind --leak-check=full --show-leak-kinds=all ./dynamic
工程习惯

AddressSanitizer 会在越界或释放后使用时立刻报错并打印调用栈，定位速度远超“加 printf”。发布版本不要带 sanitizer（有性能开销），但测试和 CI 应该带。

动手练习 · 第 11 讲
  1. 写一个动态数组：支持 push 扩容（容量翻倍）、free 释放。
  2. 下面的代码有几处问题？
    int *p = malloc(10 * sizeof(int)); p[10] = 1; free(p); free(p);
  3. 解释 calloc 和 malloc + memset 的区别。
  4. 用 -fsanitize=address 编译并运行一个故意越界的程序，读一遍报错信息。
参考答案与思路

1. 结构体保存 data、len、cap；len == cap 时 realloc 到 cap * 2，用临时指针接返回值；销毁时 free 并把字段清零。

2. 三处：p[10] 越界（合法下标 0–9）；没有检查 malloc 是否失败；free(p) 两次是双重释放。另外 free 后没有置空。

3. calloc 语义上把内存初始化为全 0 位，且会检查乘法溢出；malloc + memset 效果类似，但多一次函数调用，且 memset 按字节写 0，对某些特殊表示不保证是“空值”（对整数和指针通常是）。

4. ASan 会输出 “heap-buffer-overflow”，给出读写地址、分配位置和越界位置两条调用栈。

自测：realloc 返回 NULL 时，原来的内存块会怎样？

失败时 realloc 不改动原块，返回 NULL。所以要用临时指针接返回值，失败时继续持有并最终释放原指针。

本讲小结

  • 作用域、存储期、链接是三件不同的事。
  • 栈自动管理、堆手动管理、静态区活到程序结束。
  • malloc 必须检查 NULL；realloc 必须用临时指针。
  • 所有权要在接口层面约定清楚，否则泄漏与双重释放不可避免。
  • 用 ASan / Valgrind 代替肉眼找内存错误。
