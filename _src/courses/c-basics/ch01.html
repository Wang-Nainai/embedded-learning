1.1先搞清楚：计算机到底执行什么

你写的 hello.c 是一个 UTF-8 文本文件，里面是给人看的字符。CPU 不认识 printf，它只认识一串二进制编码的指令。两者之间隔着一个翻译过程，这个过程由工具链完成。

打个比方

你写的 .c 像一份中文菜谱。预处理是把“参见另一本配方书”的内容抄进来；编译是把菜谱翻译成厨房操作步骤；汇编是把步骤编成机器能识别的动作编号；链接是把半成品、餐具和灶台配齐。四步都成功，菜才能上桌。

类比的边界：编译器不会“执行”菜谱，链接器也不会尝味道。链接成功只说明所有符号都找到了，不说明程序逻辑正确。

1.2四个阶段，各自负责什么

预处理（Preprocessing）　处理以 # 开头的行：展开 #include、替换宏、裁剪条件编译。输出仍然是 C 代码，通常叫翻译单元。
编译（Compilation）　做词法、语法、类型检查，把 C 代码翻译成汇编。绝大多数“语法错误”“类型不匹配”在这一步报出。
汇编（Assembly）　把汇编翻译成机器指令，生成目标文件 .o（Windows 上是 .obj）。目标文件里还有没填上的地址，叫重定位项。
链接（Linking）　合并多个目标文件和库，解析符号引用，分配最终地址，生成可执行文件。这一步报的是“找不到某个函数/变量”。

1.3第一个程序：逐行读懂

#include int main(void) { printf("Hello, C!\n"); return 0; } Hello, C!
  • #include <stdio.h> 让编译器看到 printf 的声明。它不会把 printf 的实现复制进来；实现躺在 C 运行库里，链接时才被接上。尖括号表示在系统头文件目录里找，双引号表示先在当前工程目录找。
  • int main(void) 是宿主环境（hosted）的标准入口。返回类型必须是 int，void 表示不接受参数。void main() 不是标准写法，换个编译器就可能出问题。
  • printf 里的 \n 是换行符，占一个字节。字符串字面量末尾还会由编译器自动补一个 '\0'，所以 "Hello, C!\n" 实际占 11 个字节。
  • return 0; 把 0 返回给运行环境，表示正常结束。C99 起，main 走到末尾等价于返回 0，但显式写出来更清楚。
易错

把 printf 写成 print、把分号写成中文分号、把 \n 写成 /n，是初学者最常见的三类错误。中文标点在编译器眼里是完全不同的字符，报错信息往往指向“看起来没问题”的那一行。

1.4编译、运行与常用选项

打开终端，进入源文件所在目录。GCC 和 Clang 的用法基本一致：

gcc -std=c11 -Wall -Wextra -Wpedantic -O2 hello.c -o hello ./hello # Linux / macOS .\hello.exe # Windows PowerShell
本教程默认使用的编译选项
选项作用为什么建议加
-std=c11按 C11 标准编译避免编译器默认开启一堆扩展，减少“换个编译器就编不过”的情况。
-Wall -Wextra打开常用警告未初始化、格式串不匹配、有符号比较等问题会在运行前暴露。
-Wpedantic对非标准扩展告警帮你区分“标准 C”和“这个编译器恰好接受”。
-O0 -g不优化 + 调试信息调试时变量不会被优化掉，断点行号也对得上。
-O2常用优化发布版本使用；优化后单步调试可能“跳来跳去”，属正常现象。
-Werror把警告当错误团队协作或 CI 中推荐；初学阶段先看清警告内容，别急着全开。

如果想亲眼看每个阶段的产物，可以让 GCC 停在中间：

gcc -std=c11 -E hello.c -o hello.i # 只预处理 gcc -std=c11 -S hello.c -o hello.s # 编译到汇编 gcc -std=c11 -c hello.c -o hello.o # 汇编到目标文件 gcc hello.o -o hello # 链接
标准怎么说

C 标准只规定程序的语义，不规定编译器必须生成什么指令、可执行文件必须是什么格式。.exe、ELF、.hex 都是平台约定，不是 C 语言的一部分。这也解释了为什么同一段代码在 PC 和单片机上需要不同的工具链。

1.5三类错误，三种排查方向

类型发生时间典型信息先查什么
编译错误翻译阶段expected ';' before '}'
implicit declaration of function		报错行和它上一行；括号、分号、头文件、函数名拼写。
链接错误链接阶段undefined reference to 'foo'
multiple definition of 'x'		函数有没有定义、源文件有没有参与编译、库的顺序和路径。
运行时错误程序运行中段错误、结果不对、偶发崩溃越界、空指针、未初始化、释放后使用；用调试器与检查工具。

编译错误是最好处理的：编译器已经告诉你位置。链接错误次之：它说明“名字对不上”。真正耗时的是第三类——程序能跑，但结果是错的，甚至只在特定输入下崩溃。后面的第 6、7、11 讲会反复处理这类问题。

正确做法

每次写完一小段就编译一次，不要攒两百行再按编译键。编译器是你最便宜、最快、最不知疲倦的代码审查员。

动手练习 · 第 1 讲
  1. 把 hello.c 的字符串改成你的名字，重新编译运行。
  2. 故意删掉 main 后面的一个分号，观察报错行号指向哪里。
  3. 故意把 printf 改成 print，看这是编译错误还是链接错误，并解释原因。
  4. 用 -E 生成 .i 文件，搜索 printf，看看它的声明长什么样。
参考答案与思路

2. 报错通常指向缺失分号的下一行，因为编译器要读到下一个记号才能确定上一句没结束。所以看到“expected ';'”时，先看上一行。

3. 是链接错误（严格说还会先出现隐式声明警告）。编译器允许“只声明未定义”的调用，直到链接阶段才发现没有 print 这个符号。加 -Werror=implicit-function-declaration 可以让它在编译期就失败。

4. 会看到类似 extern int printf (const char *__restrict __format, ...); 的声明——只有接口，没有函数体。

自测：程序报 undefined reference to 'add'，最可能的原因是？

这是链接期的符号解析失败：编译器见过 add 的声明，所以不报语法错；链接器在所有目标文件和库里找不到它的定义，于是报未定义引用。参数类型错误会在编译期报错，局部变量问题不会导致链接失败。

本讲小结

  • C 程序要经过预处理、编译、汇编、链接四步才变成可执行文件。
  • 编译错误看语法和类型，链接错误看符号和文件清单，运行时错误看内存和逻辑。
  • 编译成功只证明“语法和符号没问题”，不证明程序正确。
  • 从第一天起就用 -Wall -Wextra 编译，把警告当朋友。
