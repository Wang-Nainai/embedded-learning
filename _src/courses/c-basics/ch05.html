5.1函数是“契约”，不是“代码块”

函数把一段逻辑封装成一个可以按名字调用的接口：调用者只需要知道“传什么、返回什么”，不需要知道里面怎么实现。这是 C 语言里唯一的大规模复用手段，也是后面模块化、驱动接口的基础。

#include /* 函数声明（原型）：告诉编译器“有这么一个函数” */ int add(int a, int b); int main(void) { printf("%d\n", add(2, 3)); return 0; } /* 函数定义：真正的实现 */ int add(int a, int b) { return a + b; } 5

声明可以出现多次，定义只能有一次（同一个程序中）。声明的作用是让编译器检查调用处的参数个数和类型；没有声明就调用，在老标准里会被当成“返回 int、参数未知”，这是很多诡异 bug 的来源。C99 起标准不再允许隐式声明（要求编译器给出诊断），但不少编译器默认只给警告；C23 起则直接报错。

5.2调用发生时，栈上发生了什么

每次函数调用，运行时都会在栈上分配一块区域，叫栈帧（stack frame）。里面通常放：返回地址、上一帧的栈底指针、参数、局部变量、以及需要保存的寄存器。函数返回时，整块栈帧被丢弃——这也是为什么局部变量在函数返回后就不存在了。

动手看

swap 为什么改不了实参

单步走完一次 swap(a, b)。注意每一帧里的变量是独立的副本，返回后 main 的 a、b 原封不动。

想让 swap 真正交换，必须传地址：void swap(int *x, int *y)，函数里用 *x 改写目标内存。

5.3值传递：C 只有一种参数传递方式

C 的函数参数永远是按值传递。所谓“传地址”，传的也是地址这个值（一份指针副本）。所以：

#include void swap_wrong(int x, int y) /* 只交换了副本 */ { int t = x; x = y; y = t; } void swap_ok(int *x, int *y) /* 通过地址改写调用者的内存 */ { int t = *x; *x = *y; *y = t; } int main(void) { int a = 3, b = 5; swap_wrong(a, b); printf("after wrong: a=%d b=%d\n", a, b); swap_ok(&a, &b); printf("after ok: a=%d b=%d\n", a, b); return 0; } after wrong: a=3 b=5 after ok: a=5 b=3

传大结构体时，按值传递会复制整个结构体（可能几十字节），既慢又容易让人误以为函数能修改原对象。经验规则：需要修改或结构体较大时传指针，只读且很小（如两个 int）时传值。

5.4返回值的三个坑

/* 坑 1：返回局部数组的地址——函数返回后数组已销毁 */ char *bad_name(void) { char buf[32] = "temp"; return buf; /* 悬空指针，调用者一用就出错 */ } /* 坑 2：返回局部结构体是合法的（按值复制），但别返回它的地址 */ struct Point { int x, y; }; struct Point make_point(int x, int y) { struct Point p = { x, y }; return p; /* 合法：返回的是副本 */ } /* 坑 3：函数声明了返回值却忘记 return */ int maybe(void) { int x = 1; /* 没有 return，调用者得到不确定值 */ }
易错

“返回局部变量的地址”在编译时通常只给一个 -Wreturn-local-addr 警告，程序还能跑，直到某次调用把栈覆盖才崩溃——这种偶发崩溃最难查。要返回字符串，请让调用者传缓冲区进来，或者用 malloc 分配（并约定谁来 free）。

#include int counter(void) { static int n = 0; /* 只初始化一次，函数返回后仍然存在 */ n++; return n; } int main(void) { printf("%d %d %d\n", counter(), counter(), counter()); /* 顺序未指定！ */ int a = counter(); int b = counter(); printf("%d %d\n", a, b); return 0; } 1 2 3 4 5
标准怎么说

上面第一行 printf 的输出顺序其实未指定：函数参数的求值顺序标准没有规定。示例里恰好是 1 2 3，但换编译器可能变成 3 2 1。凡是依赖求值顺序的代码都不可移植——第二行拆成两条语句才是正确写法。

static 在 C 里有三种含义：函数内的 static 局部变量（静态存储期，只初始化一次）；文件作用域的 static 函数/变量（内部链接，别的 .c 看不到）；以及 C99 的数组参数 static（承诺至少有 n 个元素，日常很少用）。前两种最常用，第二种会在第 10 讲多文件时再次出现。

自测：函数返回局部数组的地址，最可能的后果是？

局部数组在栈上，函数返回后栈帧失效，返回的地址指向一块随时会被覆盖的内存。编译器通常只给警告，运行时可能“看起来正常”，直到栈被别的调用覆盖。

本讲小结

  • 声明让编译器检查调用，定义只能有一份。
  • 每次调用都会压栈，参数是副本，返回后栈帧销毁。
  • C 只有值传递；“传地址”传的是指针的值。
  • 不要返回局部变量的地址；返回局部结构体的值是可以的。
  • static 局部变量活到程序结束，只初始化一次。
