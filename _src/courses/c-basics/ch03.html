不要背这张表。记住三条规则就够了：单目高于双目、算术 > 移位 > 关系 > 相等 > 位运算 > 逻辑、拿不准就加括号。加括号不丢人，读不懂的表达式才丢人。

3.2四个经典优先级陷阱

int a = 1, b = 2, c = 3; /* 1. 关系运算高于位运算：a & b == c 等价于 a & (b == c) */ if (a & b == c) { } /* 先算 b==c 得 0，再算 a&0 */ /* 2. 赋值低于比较：if (x = 0) 是赋值，不是比较 */ int x = 5; if (x = 0) { } /* 条件恒假，且 x 被改成 0 */ /* 3. 后缀 ++ 高于 *：*p++ 等价于 *(p++)，指针先移动 */ int arr[3] = {10, 20, 30}; int *p = arr; int v = *p++; /* v=10, p 指向 arr[1] */ /* 4. 逗号运算符优先级最低 */ int y = (1, 2, 3); /* y = 3，不是 1 */
工程习惯

打开 -Wall 后，if (x = 0) 会得到 -Wparentheses 警告。更稳的写法是把常量放左边：if (0 == x)，一旦漏写等号就会直接编译失败。现代编译器已经能拦住大部分此类错误，但习惯仍然值得保留。

3.3整数提升与寻常算术转换

在真正做算术之前，C 会先把小的整数类型“抬”到 int，这叫整数提升（integer promotion）。char、short、位域，以及枚举，只要 int 能表示它的全部值，就会变成 int。

#include int main(void) { unsigned char a = 200, b = 100; printf("%d\n", a + b); /* 300：先提升为 int，再相加 */ printf("%zu\n", sizeof(a + b)); /* 4：表达式类型是 int */ unsigned char c = (unsigned char)(a + b); printf("%u\n", c); /* 44：赋值时才截断 */ return 0; } 300 4 44

两个操作数类型不同时，还会发生寻常算术转换：向“能容纳更多值”的类型靠拢。大致顺序是 int → unsigned int → long → unsigned long → long long → unsigned long long → float → double → long double。真正危险的是有符号和无符号相遇：有符号会被转成无符号。

#include int main(void) { int i = -1; unsigned int u = 1; if (i < u) { printf("-1 < 1u 成立\n"); } else { printf("-1 < 1u 不成立：i 被转成了 4294967295\n"); } /* 循环变量用无符号，倒序循环会翻车 */ for (unsigned int k = 3; k >= 0; k--) { printf("%u ", k); /* 打印 3 2 1 0 后继续，k-- 回绕成 4294967295 */ if (k == 0) break; /* 没有这句就是死循环 */ } return 0; } -1 < 1u 不成立：i 被转成了 4294967295 3 2 1 0
工程习惯

在 GCC/Clang 开启 -Wsign-compare（通常随 -Wextra）时，这段代码会给出警告——这正是我们想观察的现象。真实项目里不要忽略它：绝大多数“有符号和无符号比较”的警告背后，都藏着一个边界条件错误。

易错

把 strlen(s) - 1 直接和 0 比较也会踩这个坑：strlen 返回 size_t，空串时 0 - 1 变成一个巨大的正数，循环条件永远成立。正确写法是先判断长度是否为 0，或者用 int n = (int)strlen(s);（确认长度不会超过 INT_MAX）。

3.4短路求值：不只是省事，更是安全

&& 和 || 保证从左到右求值，并且一旦结果确定就停止。这不是优化，是语言规则。

if (p != NULL && p->value > 0) { /* p 为空时右边不会执行，安全 */ use(p->value); } if (count == 0 || data[count - 1] == 0) { /* count 为 0 时不会越界访问 */ /* ... */ }

反过来，如果右边有副作用，短路会让你“以为执行了其实没执行”：

int i = 0; int a[3] = {0}; a[i++] = 1; /* i 变成 1，a[0]=1，顺序明确 */ int x = i++ + i++; /* 未定义行为：同一表达式中对 i 多次无序列修改 */
标准怎么说

两个序列点之间对同一对象多次修改，或者既修改又读取（读取是为了决定写入值的情况除外），都是未定义行为。i++ + i++、a[i] = i++ 都属于这一类。不要试图猜编译器会给出什么结果。

3.5位运算：嵌入式的日常语言

&（与）、|（或）、^（异或）、~（取反）、<<（左移）、>>（右移）。它们在通信协议、寄存器配置、掩码提取里出现频率极高。

位运算实验台

输入两个 0–255 的整数，选一个运算，同时看二进制和十进制结果。注意 ~ 会把结果变成负数（因为 int 是 32 位）。

二进制按 8 位显示，方便观察字节级操作；实际运算在 int（32 位）上进行。

三个最常用的套路，先混个脸熟，第 2 册会展开讲：

unsigned int reg = 0; reg |= (1u << 3); /* 置位：把第 3 位置 1 */ reg &= ~(1u << 3); /* 清位：把第 3 位置 0 */ reg ^= (1u << 3); /* 翻转：第 3 位取反 */ int on = (reg >> 3) & 1u; /* 读取：取出第 3 位 */ /* 取出低 4 位，其余清零 */ unsigned int low = reg & 0x0Fu;
工程习惯

写 1 << 31 是未定义行为：1 是 int，左移 31 位会溢出有符号类型。要写 1u << 31 或 1UL << 31。这个细节在第 2 册讲寄存器时非常关键。

动手练习 · 第 3 讲
  1. 不用编译器，判断 -1 < sizeof(int) 的真假，并解释。
  2. 写一个表达式，取出 x 的第 4–7 位（从 0 开始计数），结果右对齐。
  3. 把 if (x = 0) 改写成编译器一定会警告或报错的写法。
  4. 解释 *p++ 与 (*p)++ 的区别。
参考答案与思路

1. 假。sizeof 返回 size_t（无符号），比较时 -1 被转成该无符号类型的最大值，所以 -1 < 4 不成立。编译器通常会给出 -Wsign-compare 警告。

2. (x >> 4) & 0x0F。先右移把目标位对齐到最低位，再用掩码清掉其他位。

3. if (0 == x)；或者打开 -Wparentheses 并保留 if (x = 0)。

4. *p++ 先取 *p 的值，再把指针 p 加 1；(*p)++ 把 p 指向的那个值加 1，指针不动。

自测：unsigned char a = 250; int b = a + 10;，b 的值是？

a 先被整数提升为 int，250+10=260，结果赋给 int b，不截断。只有在把 260 存回 unsigned char 时才会变成 4。

本讲小结

  • 优先级记三条主线即可，复杂表达式一律加括号。
  • 小整数参与运算会先提升为 int，赋值时才截断。
  • 有符号与无符号混算会把有符号转成无符号，比较和循环都要小心。
  • && / || 短路是语言规则，可用来做空指针保护，但别在右边放必要副作用。
  • 位运算的四个动作：置位、清位、翻转、读取。
