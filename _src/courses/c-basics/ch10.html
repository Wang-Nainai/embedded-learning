10.1预处理器：编译之前的“文本替换”

预处理器不认识 C 语法，它只做四件事：把 #include 的文件内容搬进来、替换 #define 的宏、按 #if 裁剪代码、处理 #pragma 等指令。它输出的仍然是一份（很长的）C 源文件。

gcc -std=c11 -E main.c -o main.i # 只看预处理结果 gcc -std=c11 -E -dM main.c # 列出所有预定义宏
标准怎么说

宏替换是记号级的文本替换，不检查类型、不遵守作用域。这也是宏容易出事的原因：它看起来像函数，行为却完全按文本展开。

10.2宏的三个陷阱与正确写法

/* 陷阱 1：没有括号，优先级被破坏 */ #define SQUARE_BAD(x) x * x SQUARE_BAD(1 + 2) /* 展开成 1 + 2 * 1 + 2 = 5，不是 9 */ /* 修正：给参数和整体都加括号 */ #define SQUARE(x) ((x) * (x)) /* 陷阱 2：参数被求值两次 */ #define MAX_BAD(a, b) ((a) > (b) ? (a) : (b)) int m = MAX_BAD(i++, j++); /* i 或 j 可能被加两次 */ /* 修正：用 inline 函数，参数只求值一次，还能类型检查 */ static inline int max_int(int a, int b) { return a > b ? a : b; } /* 陷阱 3：宏展开后语法不完整 */ #define LOG(msg) printf("%s\n", msg); if (ok) LOG("done"); /* 展开成 if (ok) printf(...);; 后面多一个空语句 */ else LOG("fail"); /* 编译错误：else 没有对应的 if */ /* 修正：用 do { } while (0) 包起来 */ #define LOG2(msg) do { printf("%s\n", msg); } while (0)
工程习惯

能用 static inline 函数就不要用函数宏：有类型检查、参数只求值一次、调试器能进去。宏只保留给“需要字符串化/拼接记号”或“编译期条件”的场合，例如 #define ARRAY_LEN(a) (sizeof(a) / sizeof((a)[0]))。

10.3条件编译：一份代码，多种配置

#ifndef CONFIG_H #define CONFIG_H #define APP_VERSION "1.0.3" /* 调试开关：编译时用 -DDEBUG=1 打开 */ #ifndef DEBUG #define DEBUG 0 #endif #if DEBUG # define LOG(fmt, ...) printf("[%s:%d] " fmt "\n", __FILE__, __LINE__, __VA_ARGS__) #else # define LOG(fmt, ...) ((void)0) #endif #endif /* CONFIG_H */
  • #ifdef X 只判断“有没有定义”，#if X 判断“值是不是非 0”。用 #if DEBUG 更安全，因为 -DDEBUG=0 时它仍然关闭。
  • __FILE__、__LINE__ 是预定义宏，常用于日志和断言。
  • 可变参数宏 ... 与 __VA_ARGS__ 是 C99 特性；空参数时的逗号问题在 C23 之前需要技巧处理。

10.4头文件里该放什么

放在 .h放在 .c原因
函数声明（原型）函数定义头文件会被多个 .c 包含，定义放进去会重复定义
struct / enum / typedef 定义该类型的操作函数实现类型需要在调用处可见
extern 变量声明变量定义声明不分配存储，定义才分配
宏、常量—宏没有链接属性，只能靠包含
static inline 小函数—每个翻译单元各自内联，不产生外部符号
#ifndef MY_MODULE_H #define MY_MODULE_H /* 头文件里只放“声明”和“类型” */ #include #define MY_NAME_MAX 32 typedef struct { int id; char name[MY_NAME_MAX]; } Item; /* 声明：告诉编译器有这些函数 */ void item_init(Item *it, int id, const char *name); const char *item_name(const Item *it); #endif /* MY_MODULE_H */

#ifndef / #define / #endif 叫包含守卫，防止同一个头文件被重复展开。现代编译器也支持 #pragma once，更简洁，但它是扩展而非标准；包含守卫的可移植性最好。

10.5一个真正的多文件项目

三个文件：student.h 放接口，student.c 放实现，main.c 负责调用。

#ifndef STUDENT_H #define STUDENT_H #include #define STUDENT_NAME_MAX 20 typedef struct { int id; char name[STUDENT_NAME_MAX]; double score; } Student; void student_print(const Student *s); int student_set_name(Student *s, const char *name); double student_average(const Student *arr, size_t n); #endif /* STUDENT_H */ #include "student.h" #include #include void student_print(const Student *s) { printf("%d\t%s\t%.1f\n", s->id, s->name, s->score); } int student_set_name(Student *s, const char *name) { size_t len = strlen(name); if (len >= STUDENT_NAME_MAX) { return -1; /* 名字太长，拒绝并保持原值 */ } memcpy(s->name, name, len + 1); /* 连 '\0' 一起复制 */ return 0; } double student_average(const Student *arr, size_t n) { if (arr == NULL || n == 0) { return 0.0; } double sum = 0.0; for (size_t i = 0; i < n; i++) { sum += arr[i].score; } return sum / (double)n; } #include "student.h" #include int main(void) { Student list[3] = { {1, "Ada", 92.5}, {2, "Bob", 78.0}, {3, "Cara", 88.5} }; if (student_set_name(&list[1], "Bobby") != 0) { printf("名字过长\n"); } for (size_t i = 0; i < 3; i++) { student_print(&list[i]); } printf("平均分 %.2f\n", student_average(list, 3)); return 0; } gcc -std=c11 -Wall -Wextra -Wpedantic main.c student.c -o app ./app 1 Ada 92.5 2 Bobby 78.0 3 Cara 88.5 平均分 86.33

也可以分开编译再链接，这一步能让你看清“目标文件”和“链接”的关系：

gcc -std=c11 -Wall -Wextra -c main.c -o main.o gcc -std=c11 -Wall -Wextra -c student.c -o student.o gcc main.o student.o -o app

文件多了以后，手写命令不现实，用 Makefile：

CC := gcc CFLAGS := -std=c11 -Wall -Wextra -Wpedantic -O2 -g TARGET := app OBJS := main.o student.o $(TARGET): $(OBJS) $(CC) $(OBJS) -o $@ %.o: %.c student.h $(CC) $(CFLAGS) -c $< -o $@ clean: rm -f $(OBJS) $(TARGET) .PHONY: clean
易错

Makefile 里命令行前面必须是Tab，不是空格。这是初学者最常遇到的“missing separator”错误。

10.6链接错误的三种常见原因

错误信息含义排查
undefined reference to 'foo'声明了，但没有定义参与链接是不是忘了把 foo.c 加进编译命令？函数名拼写是否一致？
multiple definition of 'x'同一个符号被定义了两次变量是不是写在头文件里了？头文件有没有包含守卫？
undefined reference to 'sqrt'数学库没链接命令末尾加 -lm（库要放在源文件之后）
标准怎么说

C 采用“分别编译”模型：每个 .c 独立编译成一个翻译单元，编译器看不到别的 .c 里有什么。跨文件调用只能靠声明建立约定，靠链接器把符号接上。这也是为什么头文件里的声明必须和定义严格一致——编译器无法替你检查。

动手练习 · 第 10 讲
  1. 把上面的三文件项目亲手编译运行一遍，然后故意删掉 student.c 的编译参数，观察链接错误。
  2. 写一个 ARRAY_LEN(a) 宏，并说明为什么它不能用于函数参数里的数组。
  3. 用条件编译实现：DEBUG 为 1 时打印日志，为 0 时日志代码完全不参与编译。
  4. 解释头文件里写 int counter = 0; 会发生什么，正确写法是什么。
参考答案与思路

2. #define ARRAY_LEN(a) (sizeof(a) / sizeof((a)[0]))。它依赖 sizeof 能看到数组类型；数组传参后退化为指针，sizeof 得到指针大小，结果错误。

3. 用 #if DEBUG 包住 printf，或者定义空宏 #define LOG(...) ((void)0)。后者在语法上仍是完整语句，不会留下空 if。

4. 每个包含该头文件的 .c 都会定义一个 counter，链接时报告 multiple definition。正确做法：头文件写 extern int counter;，在某个 .c 里写 int counter = 0;。

自测：#define SQR(x) x*x，SQR(2+3) 展开后等于？

宏是纯文本替换：SQR(2+3) 变成 2+3*2+3，按优先级算出 11。写成 ((x)*(x)) 才能得到 25。

本讲小结

  • 预处理只做文本级操作，不检查类型和作用域。
  • 函数宏必须给参数和整体加括号，并避免参数被多次求值。
  • 头文件放声明和类型，定义放 .c，并用包含守卫。
  • 多文件项目要分别编译、统一链接；库的链接顺序可能影响结果。
  • “未定义引用”先查文件清单和拼写，“重复定义”先查头文件。
