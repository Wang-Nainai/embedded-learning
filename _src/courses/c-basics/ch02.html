2.1变量到底是什么

变量不是数学里的未知数 x。它由四样东西组成：一个名字、一个类型、一块存储位置、当前的值。类型决定这块内存有多宽、里面的 0/1 该怎么解释。

同样 4 个字节 0x41 0x42 0x43 0x44，按 int 读是 1145258561，按 char[4] 读是 "ABCD"。内存本身没有类型，类型是你和编译器之间的约定。

2.2基本类型与 sizeof

C 只保证“相对大小”，不保证绝对字节数：char 恰好 1 字节（1 字节不一定 8 位，但在主流平台上就是 8 位），short ≤ int ≤ long ≤ long long。想知道你机器上的真实大小，用 sizeof 测，不要背。

#include int main(void) { printf("char %zu\n", sizeof(char)); printf("short %zu\n", sizeof(short)); printf("int %zu\n", sizeof(int)); printf("long %zu\n", sizeof(long)); printf("long long %zu\n", sizeof(long long)); printf("float %zu\n", sizeof(float)); printf("double %zu\n", sizeof(double)); printf("pointer %zu\n", sizeof(void *)); return 0; } char 1 short 2 int 4 long 4 long long 8 float 4 double 8 pointer 8

上面是一次 64 位 Windows + Clang 的实际输出。注意 long 只有 4 字节：Windows 采用 LLP64 模型（long 仍是 32 位），而 64 位 Linux / macOS 采用 LP64（long 是 8 字节）。同一份代码换个系统，sizeof(long) 就变了。

这就是为什么跨平台代码更愿意用 <stdint.h> 里的 int32_t、uint16_t——它们明确要求“恰好这么多位”，编译器不支持就编不过，而不是悄悄换个宽度。在 32 位平台或某些嵌入式编译器上，int 也可能是 2 字节，指针是 4 字节。

标准怎么说

sizeof 的结果类型是 size_t，一种无符号整数类型，打印时用 %zu。用 %d 打印 size_t 在 64 位平台上是未定义行为，常见后果是输出被截断或显示成负数。

2.3整数：补码、范围与溢出

现代计算机用补码表示有符号整数。以 8 位为例：0000 0001 是 1，1111 1111 是 -1，1000 0000 是 -128。补码的好处是减法可以当加法做，硬件只需要一套加法器。

这个数放得进去吗？

选一个类型，输入一个十进制数，看它在内存里的位模式、是否越界，以及越界后会发生什么。

位模式按“高位在左”显示。负数用补码：把绝对值的二进制取反再加 1。

关键区别只有一句话：无符号溢出是良定义的（按 2N 取模回绕），有符号溢出是未定义行为。

#include #include int main(void) { unsigned int u = UINT_MAX; u = u + 1; /* 良定义：回绕到 0 */ printf("unsigned wrap: %u\n", u); int i = INT_MAX; /* i + 1 是有符号溢出：未定义行为，不要写这种代码 */ printf("INT_MAX = %d, INT_MAX+1 不能依赖任何结果\n", i); return 0; } unsigned wrap: 0 INT_MAX = 2147483647, INT_MAX+1 不能依赖任何结果
易错

“有符号溢出会变成负数”是一个流传很广的半真命题。它在你机器上可能确实回绕，但标准没有保证，开启 -O2 后编译器可以假设溢出不会发生，从而删掉你的检查。要检测溢出，请在运算之前比较边界，而不是算完再判断。

#include #include int add_checked(int a, int b, int *out) { if ((b > 0 && a > INT_MAX - b) || (b < 0 && a < INT_MIN - b)) { return -1; /* 会溢出，拒绝计算 */ } *out = a + b; return 0; } int main(void) { int r = 0; if (add_checked(INT_MAX, 1, &r) != 0) { printf("overflow rejected\n"); } return 0; } overflow rejected

2.4浮点数：为什么 0.1 + 0.2 不等于 0.3

float 和 double 按 IEEE 754 存储：1 位符号、若干位指数、若干位尾数。float 只有 24 位有效二进制位，大约 7 位十进制有效数字；double 有 53 位，大约 15–16 位十进制有效数字。0.1 在二进制里是无限循环小数，只能存一个近似值。

#include #include int main(void) { double a = 0.1 + 0.2; printf("%.17f\n", a); /* 0.30000000000000004 */ printf("a == 0.3 ? %d\n", a == 0.3); double eps = 1e-9; printf("close enough ? %d\n", fabs(a - 0.3) < eps); return 0; } 0.30000000000000004 a == 0.3 ? 0 close enough ? 1
  • 比较浮点数要用“误差小于容差”，而不是 ==。容差取多大取决于量级：金额用分（整数）存，比用 double 存元更稳。
  • float 的有效数字少，累加几千次以后误差会明显。需要高精度累加时用 double，或者 Kahan 求和。
  • NaN != NaN 永远为真。判断 NaN 用 isnan()，不要用 x == x 之外的写法。

工程习惯

不要写“魔法数字”。给常量起名字，并用 const 或 enum 表达意图：const int MAX_USERS = 64; 比在十个地方写 64 更容易维护。注意 const 变量在 C 里默认是外部链接，放在头文件里定义会重复定义，正确做法是头文件写 extern const int MAX_USERS;，某个 .c 里定义。

参考答案与思路

2. 结果是 0。运算时 c 先被提升为 int，255+1=256，赋值回 unsigned char 时按 256 取模，得 0。注意“提升”发生在运算中，“截断”发生在赋值时。

3. 用第 2.3 节的 add_checked 思路：先判断 b > 0 && a > INT_MAX - b 或 b < 0 && a < INT_MIN - b。

4. float 只有 24 位有效位，能精确表示的最大连续整数是 224=16777216。16777217 需要 25 位，只能舍入到最近的偶整数 16777216。

自测：unsigned char c = 250; c += 10; 之后 c 的值是？

无符号运算按 28=256 取模：260 mod 256 = 4。如果 c 是 signed char，260 超出范围，赋值时的转换结果由实现定义（常见是 -6），同样不该依赖。

本讲小结

  • 类型决定宽度和解释方式；sizeof 是唯一可靠的测量手段。
  • 无符号溢出按模回绕；有符号溢出是未定义行为，必须在运算前检查。
  • 浮点数是近似值，比较要用容差；金额优先用整数最小单位存储。
  • 注意八进制前导 0、U/L 后缀和 size_t 的格式符。
