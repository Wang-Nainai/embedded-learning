1.1两台机器说话，需要约定什么

网络通信的本质是“两台机器上的两个程序交换字节”。要让它可靠发生，至少要约定五件事：

怎么连　物理介质与接口（网线、Wi-Fi、光纤）。
怎么找到对方　地址（MAC、IP、域名）。
数据怎么切分　帧、包、段，各自的边界与校验。
丢了怎么办　确认、重传、超时、顺序。
字节是什么意思　应用层协议（HTTP、MQTT、自定义）。

把这些问题分层处理，就是网络架构的核心思想：每一层只解决一类问题，并向上提供接口。

1.2OSI 七层与 TCP/IP 四层

TCP/IP 四层OSI 对应典型协议典型设备/概念数据单位
应用层应用 / 表示 / 会话HTTP、DNS、MQTT、TLS浏览器、客户端、Broker消息
传输层传输TCP、UDP端口、套接字段（segment）/ 数据报
网络层网络IP、ICMP、ARP*路由器包（packet）
链路层数据链路 / 物理Ethernet、Wi-Fi、PPP交换机、网卡帧（frame）

* ARP 常被归到链路层与网络层之间，它把 IP 地址解析成 MAC 地址，不承载上层数据。

工程习惯

排障时先问“问题在哪一层”：网线没插是链路层，IP 配错是网络层，端口没监听是传输层，返回 404 是应用层。分层不是为了考试，是为了让你知道下一步该查什么。

1.3封装：一层套一层

发送数据时，每一层都会在数据前面加上自己的头部（有时还有尾部）。接收时再逐层剥掉。这个过程叫封装 / 解封装。

动手看

一条消息被套了多少层

点击“发送”，看应用数据如何被 TCP、IP、以太网依次加上头部；再点“接收”，看它如何被逐层剥开。

每层只关心自己的头部，不关心上层载荷的内容——这就是分层的价值。

1.4客户端与服务器

“客户端/服务器”不是指硬件，而是指角色：主动发起连接的一方是客户端，被动等待连接的一方是服务器。同一个程序可以既是客户端又是服务器。

角色典型行为例子
客户端知道服务器地址，主动连接，发请求浏览器、手机 App、ESP32 上报程序
服务器监听端口，接受连接，处理请求Web 服务器、MQTT Broker
对等（P2P）双方既发又收，角色对等局域网文件传输、部分音视频

服务器要同时服务多个客户端，通常用“每连接一个线程/协程”或“事件循环（epoll/kqueue）”。嵌入式设备资源有限，通常只做客户端，或者做轻量服务器（如配置页面）。

1.5一次访问，经过哪些设备

浏览器 → 本机协议栈 → 网卡 → 交换机 → 路由器 → 运营商网络 → 目标服务器 ↑ ↓ └──────────────── 响应沿相反路径返回 ─────────────────────────┘
  • 交换机工作在链路层，按 MAC 转发帧，不改变 IP。
  • 路由器工作在网络层，按 IP 前缀转发包，每跳都会改 MAC、减 TTL。
  • NAT 在路由器上改写源/目的 IP 与端口，让多台内网设备共享一个公网地址。
动手练习 · 第 1 讲
  1. 把 HTTP、TCP、IP、Ethernet 分别放到 TCP/IP 四层中。
  2. “交换机根据 IP 转发”这句话对吗？为什么？
  3. 封装过程中，哪一层会加校验尾部？
  4. 客户端和服务器的区分依据是什么？
参考答案与思路

1. HTTP 应用层、TCP 传输层、IP 网络层、Ethernet 链路层。

2. 不对。交换机主要按 MAC 地址转发，不解析 IP（三层交换机除外）。

3. 以太网帧有 FCS 尾部；IP 头有校验和（仅头部）；TCP/UDP 有校验和字段。

4. 谁主动发起连接谁是客户端；角色是相对的，不是设备属性。

自测：IP 地址属于哪一层？

IP 是网络层地址，负责跨网络寻址与路由；MAC 是链路层地址，负责同一局域网内的交付；端口是传输层概念。

本讲小结

  • 网络通信要解决连接、寻址、分帧、可靠性、语义五类问题。
  • TCP/IP 四层：应用、传输、网络、链路。
  • 封装是逐层加头，解封装是逐层剥离。
  • 交换机看 MAC，路由器看 IP，NAT 改写地址与端口。
  • 客户端/服务器是角色，不是设备。
