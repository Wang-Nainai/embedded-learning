WebSocket 握手借用 HTTP：客户端发 Upgrade: websocket，服务器回 101 Switching Protocols，之后双方按帧收发，不再有 HTTP 头。

8.3HTTPS：HTTP over TLS

HTTPS 不是新协议，而是“HTTP 跑在 TLS 之上”。TLS 解决三件事：

机密性

对称加密（AES-GCM/ChaCha20）保护内容，中间人看不到明文。

完整性

AEAD 同时校验，篡改会被发现。

身份

证书链证明“服务器确实是它声称的那个”。

ClientHello　客户端提供支持的版本、套件、随机数、SNI。
ServerHello + 证书　服务器选套件，发送证书链。
验证证书　客户端检查签名链、有效期、域名、吊销状态。
密钥交换　TLS 1.3 用 ECDHE，一次往返完成。
Finished　双方确认握手完整性，开始加密传输。
易错

嵌入式设备最常见的 TLS 失败原因：设备时钟不对（证书“尚未生效”）、根证书缺失（无法验证链）、SNI 没发（服务器返回默认站点证书）、证书过期。先用 openssl s_client 在电脑上验证，再查设备。

openssl s_client -connect example.com:443 -servername example.com openssl s_client -connect example.com:443 -showcerts
工程习惯

不要在固件里关掉证书校验来“先跑通”。这等于把 HTTPS 降级成 HTTP，中间人可以随意篡改。正确做法是内置根证书、校验证书链与域名，并保证设备时间可用（NTP 或构建时间兜底）。

8.4HTTP 客户端的常见坑

  • 没有读完响应就关闭：HTTP/1.1 复用连接时，残留数据会污染下一个请求。
  • 不处理 chunked：有些响应没有 Content-Length，用分块传输。
  • 不设超时：服务器不响应时，设备永远卡住。
  • 不检查状态码：把 401/500 的响应体当成正常 JSON 解析。
  • URL 编码：查询参数里的空格、中文、特殊字符必须编码。

自测：HTTPS 相比 HTTP 多了什么？

HTTPS = HTTP + TLS。它不改变 HTTP 的语义，只是在传输层加上加密、完整性校验和服务器身份验证。

本讲小结

  • HTTP 是文本的请求-响应协议，头部以空行结束。
  • 状态码表达结果类别，设备端要检查再解析。
  • HTTP/2 多路复用，WebSocket 提供全双工。
  • HTTPS 用 TLS 提供加密、完整性与身份。
  • 证书校验不能关，时钟与根证书是常见坑。
