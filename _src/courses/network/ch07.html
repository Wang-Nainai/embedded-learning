7.1DNS：把名字翻译成地址

你记不住 142.250.72.14，但记得住 www.example.com。DNS 就是互联网的“电话簿”，把域名解析成 IP。

本机缓存　浏览器、操作系统先查缓存（含 hosts 文件）。
递归解析器　通常是运营商或公共 DNS（如 223.5.5.5）。
根服务器　告诉你“.com 的权威服务器在哪”。
顶级域服务器　告诉你“example.com 的权威服务器在哪”。
权威服务器　返回最终的 A / AAAA 记录。
缓存　按 TTL 缓存，减少后续查询。
记录含义例子
A域名 → IPv4example.com → 93.184.216.34
AAAA域名 → IPv6example.com → 2606:2800:…
CNAME别名www → example.com
MX邮件服务器example.com → mail.example.com
TXT文本记录SPF、域名验证
NS权威服务器example.com → ns1.example.com
nslookup example.com # Windows / Linux dig example.com A # Linux / macOS dig @223.5.5.5 example.com # 指定 DNS 服务器 ipconfig /flushdns # Windows 清缓存

7.2DHCP：自动拿到地址

设备刚接入网络时没有 IP，只能用广播找 DHCP 服务器。四个步骤简称 DORA：

步骤方向内容
Discover客户端广播有没有 DHCP 服务器？
Offer服务器 → 客户端给你这个地址，要不要？
Request客户端广播我要这个地址
Ack服务器 → 客户端确认，租期 N 小时

地址是“租”的，到期要续租（T1 50%、T2 87.5% 时尝试）。嵌入式设备如果 DHCP 失败，通常会落到 169.254.x.x（链路本地），表现为“连上了 Wi-Fi 但上不了网”。

7.3NAT：一个公网 IP 怎么够全家用

NAT 在路由器上改写 IP 和端口，让多台内网设备共享一个公网地址。最常见的 PAT（端口地址转换）用一个映射表：

内网 192.168.1.10:50000 → 公网 203.0.113.5:40001 内网 192.168.1.11:50000 → 公网 203.0.113.5:40002

出站时改源地址/端口，回包时按表反向改写。它解决了 IPv4 地址不足，但也带来三个限制：

  • 外网不能主动连内网，除非做端口映射/打洞。
  • 映射表有超时，长时间无流量会被回收。
  • 某些协议（FTP 主动模式、SIP）在载荷里带 IP，需要 ALG 特殊处理。
工程习惯

设备作为 TCP 客户端连服务器，NAT 不是问题；设备要做“被访问的服务器”，就必须有公网映射、内网穿透或反向连接。设计物联网架构时，优先让设备主动连出（MQTT 就是这种模式）。

检查命令结果说明
本机地址ipconfig / ip addr是否有 169.254 地址
网关连通ping 网关不通 → 链路/交换/VLAN 问题
公网 IP 连通ping 8.8.8.8通 → 路由与 NAT 正常

端口curl -v http://example.com看卡在建连还是响应

  2. DHCP 的四个步骤分别是什么？
  3. NAT 为什么能省公网 IP？代价是什么？
  4. 能 ping 通 8.8.8.8 但打不开网页，最可能是什么问题？
参考答案与思路

1. 域名数量巨大且分散管理，分层可以把查询分散到各级权威服务器，并用缓存减少根服务器压力。

2. Discover、Offer、Request、Ack。

3. 用端口区分内网连接，多个内网地址共享一个公网地址；代价是外网无法主动访问内网、映射表有状态与超时。

4. DNS 解析失败（或代理配置错误）。IP 层通，应用层域名解析不了。

自测：DHCP 的作用是？

DHCP 负责“自动配置网络参数”；DNS 负责域名解析；NAT 负责地址转换。三者经常一起出现，但职责完全不同。

本讲小结

  • DNS 分层解析域名，按 TTL 缓存。
  • DHCP 用 DORA 四步自动分配地址与参数。
  • NAT/PAT 用端口映射让多设备共享公网 IP。
  • NAT 限制外网主动访问，设备应优先主动连出。
  • 排障顺序：地址 → 网关 → 公网 IP → DNS → 端口。
