2.1MAC 地址：网卡的身份证

MAC 地址 48 位，通常写成 00:1A:2B:3C:4D:5E。前 24 位是厂商前缀（OUI），后 24 位由厂商分配。它只在同一个局域网内有效，路由器不会把 MAC 带到互联网。

类型特征用途
单播第一个字节最低位为 0发给某一块网卡
广播FF:FF:FF:FF:FF:FFARP 请求、DHCP 发现
组播第一个字节最低位为 1视频流、IPv6 邻居发现
实现细节

每块网卡的 MAC 理论上全球唯一，但很多芯片允许软件修改（MAC 地址克隆/随机化）。虚拟机和容器更是随便配。所以不能把 MAC 当作安全凭证。

2.2以太网帧

Ethernet II 帧
字段长度说明
前导码 + SFD7 + 1 字节用于时钟同步，不算帧内容
目的 MAC6 字节可以是单播/广播/组播
源 MAC6 字节发送方网卡
类型/长度2 字节0x0800 = IPv4，0x0806 = ARP，0x86DD = IPv6
载荷46–1500 字节IP 包；不足 46 字节要填充
FCS4 字节CRC32 校验，错误帧直接丢弃

MTU（最大传输单元）通常是 1500 字节。IP 包超过 MTU 就要分片，或者由上层控制报文大小（TCP 的 MSS 就是据此协商的）。

2.3交换机怎么转发

学习　收到帧时，把“源 MAC + 入端口”记进 MAC 表。
查找　看目的 MAC 在表里有没有。
转发　有就只从对应端口发出（单播）。
泛洪　没有就从除入端口外的所有端口发出。
老化　表项一段时间不用就删除，适应设备移动。

2.4冲突域与广播域

概念含义隔离设备
冲突域同时发送会冲突的范围交换机每个端口一个冲突域
广播域广播帧能到达的范围路由器 / VLAN

交换机隔离冲突域，但不隔离广播域：一个广播帧会被泛洪到所有端口。广播太多会占用带宽和 CPU，这时就用 VLAN 把一个物理交换机切成多个逻辑广播域。

工程习惯

嵌入式设备如果频繁发广播（例如设备发现协议），要考虑广播风暴的风险。能用量身定制的组播/单播，就不要用广播。

2.5VLAN 与 Trunk

VLAN 在以太网帧里插入 4 字节标签（802.1Q），用 12 位 VLAN ID 标识所属网络。交换机端口可以配置成：

  • Access：只属于一个 VLAN，接终端设备。
  • Trunk：承载多个 VLAN，接交换机/路由器，帧带标签。

对嵌入式设备来说，VLAN 通常是“网络管理员的事”；但如果你要接工业交换机、划分控制网与办公网，就需要知道设备该接 Access 口还是 Trunk 口。

  2. 交换机收到未知目的 MAC 的帧会怎么做？
  3. 广播域和冲突域分别由什么设备隔离？
  4. MTU 1500 时，一个 3000 字节的 IP 包会怎样？
参考答案与思路

1. MAC 只在链路层本地有效；路由器每跳会重新封装成新的链路层帧，源/目的 MAC 都变成当前链路两端的地址。

2. 泛洪到除入端口外的所有端口，同时学习源 MAC。

3. 冲突域由交换机端口隔离；广播域由路由器或 VLAN 隔离。

4. 若 DF=0 则分成两个片；若 DF=1 则丢弃并返回 ICMP“需要分片”。

自测：交换机主要根据什么转发帧？

普通二层交换机看目的 MAC；路由器才看目的 IP；端口号是传输层概念，交换机不解析。

本讲小结

  • MAC 是链路层地址，只在本地链路有效。
  • 以太网帧包含源/目的 MAC、类型、载荷与 FCS。
  • 交换机学习源 MAC、按目的 MAC 转发、未知则泛洪。
  • 交换机隔离冲突域，路由器/VLAN 隔离广播域。
  • MTU 决定是否需要分片。
