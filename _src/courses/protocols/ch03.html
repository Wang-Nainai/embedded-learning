3.1为什么轮询接收会丢数据

UART 接收寄存器通常只能存 1 个字节。如果 CPU 正在处理别的事，第二个字节到达时，第一个还没被读走，就会溢出（overrun）。标志位会告诉你“丢了一个字节”，但数据已经没了。

波特率一个字节时间主循环能耽误多久
9600≈ 1.04 ms约 1 ms
115200≈ 86.8 µs不到 0.1 ms
921600≈ 10.9 µs几乎不能耽误

所以高速/连续接收必须用中断或 DMA，把“搬运”与“处理”分开。

3.2中断 + 环形缓冲区

#include #include #define RX_CAP 128 static volatile uint8_t g_rx[RX_CAP]; static volatile uint16_t g_head, g_tail; static volatile uint32_t g_overrun; void USART1_IRQHandler(void) { uint32_t sr = UART_SR; if (sr & UART_SR_ORE) { g_overrun++; /* 记录溢出，读 DR 清标志 */ } if (sr & UART_SR_RXNE) { uint8_t byte = (uint8_t)UART_DR; uint16_t next = (uint16_t)((g_head + 1u) % RX_CAP); if (next != g_tail) { g_rx[g_head] = byte; g_head = next; } else { g_overrun++; /* 缓冲区满：丢弃并计数 */ } } } /* 主循环：取出所有已到达的字节 */ bool rx_pop(uint8_t *out) { if (g_head == g_tail) { return false; } *out = g_rx[g_tail]; g_tail = (uint16_t)((g_tail + 1u) % RX_CAP); return true; }
先修回顾

环形缓冲区就是一块固定数组加两个索引：head 由写入方（中断）推进，tail 由读取方（主循环）推进；索引到末尾回绕到 0。写的时候先写数据再移动 head，读的时候先取数据再移动 tail，这样对方看到指针变化时数据一定已经就绪。完整实现与满/空判定见第 2 册第 10 讲。

工程习惯

中断里只做“读寄存器 + 存缓冲区 + 计数”，不做解析、不打印。解析放在主循环或任务里。这样即使一帧很长、处理很慢，中断也能及时把字节收走。

3.3怎么知道一帧结束了

方法原理适用
固定长度收满 N 字节即一帧协议长度固定
结束符收到 \n / \r / 自定义字节文本命令、AT 指令
长度字段先读长度，再收够载荷二进制协议
空闲中断（IDLE）总线静默超过 1 个字符时间不定长帧、Modbus RTU
DMA + 半满/全满DMA 搬运，达到阈值通知高速、大批量
/* 空闲中断：一帧结束，把 DMA 收到的数据交给解析器 */ void USART1_IRQHandler(void) { if (uart_flag_get(UART_FLAG_IDLE)) { uart_flag_clear(UART_FLAG_IDLE); size_t len = dma_received_count(); parser_feed(g_dma_buf, len); /* 注意：解析可能耗时，建议只入队 */ dma_restart(g_dma_buf, sizeof g_dma_buf); } }
实现细节

IDLE 中断的判定是“接收线在 1 个字符时间内没有新边沿”。它对 Modbus RTU 的 3.5 字符间隔很友好，但对“连续高速流”不适用——流永远不空闲。此时应改用长度字段或 DMA 半满中断。

3.4DMA：让硬件搬字节

DMA 把“外设寄存器 → 内存”的搬运交给硬件，CPU 只在“半满/全满/空闲”时被通知。适合高波特率、大批量数据。

模式优点注意
普通模式简单，收满即停要手动重启，重启期间可能丢字节
循环模式不停搬运，适合连续流要处理“回绕”和“覆盖”，用半满/全满中断
双缓冲一边收一边处理配置复杂，但吞吐最高

3.5四个错误标志

标志含义处理
ORE（溢出）上一个字节还没读，新字节又到了读 DR 清除，计数告警
FE（帧错误）停止位不是高电平波特率/接线/干扰问题
NE（噪声）采样时检测到多次跳变检查上升沿、共地、屏蔽
PE（校验错）校验位不匹配双方校验配置不一致，或位错误
易错

很多 HAL 库在发生 ORE 后会“锁死”接收，必须读 SR 再读 DR 才能恢复。如果中断里只处理 RXNE、不处理 ORE，表现为“跑一段时间后再也收不到数据”。

动手练习 · 第 3 讲
  1. 115200 下，主循环每 5 ms 才轮询一次，会丢多少字节？
  2. 设计一个“以 \n 结尾”的命令接收流程，说明中断和主循环各做什么。
  3. IDLE 中断适合什么帧？不适合什么帧？
  4. ORE 标志为什么必须显式处理？
参考答案与思路

1. 5 ms / 86.8 µs ≈ 57 个字节；接收寄存器只有 1 个，其余全部丢失（具体取决于 FIFO 深度）。

2. 中断：读字节、存环形缓冲、遇到 \n 置“整行就绪”标志；主循环：取行、解析、执行。解析不放在中断里。

3. 适合不定长、帧间有明显空闲的协议（Modbus RTU）；不适合连续高速流（永远不空闲）。

4. ORE 会导致接收逻辑停摆，且必须“读 SR + 读 DR”才能清除；不处理会永久收不到数据。

自测：接收中断里最不应该做的是？

解析和执行可能耗时、可能阻塞、可能调用不可重入函数，应放到主循环或任务里。中断只负责“尽快把字节搬走”。

本讲小结

  • 轮询接收在高波特率下很容易丢数据，取决于轮询间隔与接收 FIFO 深度。
  • 中断 + 环形缓冲是标准接收路径。
  • 帧边界可用长度、结束符、IDLE 或 DMA 阈值判断。
  • DMA 适合高速/大批量，但要处理回绕与覆盖。
  • ORE/FE/NE/PE 都要显式处理并计数。
