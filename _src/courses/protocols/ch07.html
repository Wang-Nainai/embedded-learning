7.1RS-485 只负责“电气”

RS-485 规定的是差分电平、共模范围、多点总线，不规定帧格式、地址和校验。它经常和 Modbus RTU 一起出现，所以很多人误以为它们是同一个东西。

A/B 两根线的差分电平一帧有多少字节
共模电压范围（约 -7 V 到 +12 V）地址怎么分配
半双工、多点拓扑数据含义
终端与偏置（建议）校验方式
驱动能力（标准 32 单位负载）超时与重试
易错

“RS-485 通信不上”与“Modbus 协议不对”是两类问题。前者看波形、终端、方向控制；后者看地址、功能码、CRC、字节序。不要一上来就改协议代码。

7.2半双工与方向控制

RS-485 收发器通常有 DE（驱动使能）和 /RE（接收使能）两个引脚，常接在一起用一个 GPIO 控制：高电平发送，低电平接收。

void rs485_send(const uint8_t *buf, size_t len) { gpio_de(1); /* 切到发送 */ delay_us(10); /* 等收发器稳定（按器件手册） */ for (size_t i = 0; i < len; i++) { uart_putc(buf[i]); } uart_wait_tx_complete(); /* 等最后一个字节真正移出，不能只看 DR 空 */ delay_us(10); gpio_de(0); /* 释放总线，切回接收 */ }
实现细节

TXE（发送寄存器空）只表示“可以写下一个字节”，不表示“最后一个字节已经发完”。要等 TC（传输完成），否则提前切回接收会把最后一个字节的尾部截掉。

7.4CRC16：算错就永远不通

Modbus RTU 用的是 CRC-16/MODBUS：多项式 0x8005 的反射形式 0xA001，初值 0xFFFF，不反转输入输出，不做最终异或。发送时低字节在前。

#include #include uint16_t modbus_crc16(const uint8_t *data, size_t len) { uint16_t crc = 0xFFFFu; for (size_t i = 0; i < len; i++) { crc ^= data[i]; for (int b = 0; b < 8; b++) { if (crc & 1u) { crc = (uint16_t)((crc >> 1) ^ 0xA001u); } else { crc >>= 1; } } } return crc; }

7.5异常响应与超时

请求：01 03 00 00 00 02 C4 0B 响应：01 83 02 C0 F1 │ │ └─ 异常码 02：非法数据地址 │ └──── 功能码最高位置 1，表示异常 └─────── 从站地址
异常码含义
01非法功能码
02非法数据地址
03非法数据值
04从站设备故障

主站必须设置响应超时（常见 100–1000 ms，取决于波特率与从站处理时间）。超时后重试，连续失败则标记从站离线——不要无限重试，否则整个轮询周期会被拖死。

动手练习 · 第 7 讲
  1. 写一个 Modbus 读保持寄存器的请求：从站 1，起始 0x0000，读 2 个寄存器。
  2. 为什么发送完要等 TC 而不是 TXE 再切方向？
  3. CRC 算出来是 0x1234，线上两个字节的顺序是什么？
  4. 主站轮询 10 个从站，其中一个离线，如何避免拖慢整体？
参考答案与思路

1. 01 03 00 00 00 02 + CRC（CRC 低字节在前）。

2. TXE 只表示发送寄存器空，最后一个字节可能还在移位；等 TC 才能保证线上已经发完。

3. 低字节先发：34 12。

4. 每个从站单独超时 + 失败计数；离线从站降低轮询频率或跳过，避免每次轮询都等满超时。

自测：Modbus RTU 的 CRC 在线上是什么顺序？

Modbus RTU 规定 CRC 低字节先传输。很多“CRC 算对了但通信不通”的问题，都是字节序发反了。

本讲小结

  • RS-485 是电气规范，Modbus RTU 是应用协议。
  • 半双工要控制 DE/RE，切换前等 TC。
  • Modbus 帧 = 地址 + 功能码 + 数据 + CRC16（低字节在前）。
  • 异常响应把功能码最高位置 1，并带异常码。
  • 主站要有超时、重试与离线标记。
