5.1“int 是 4 字节”只是一个巧合

C 标准只规定最小范围，不规定字节数：int 至少 16 位，long 至少 32 位，long long 至少 64 位。在 8 位 MCU 上，int 常常就是 16 位；某些 DSP 上 char 甚至不是 8 位。

#include #include int main(void) { printf("CHAR_BIT = %d\n", CHAR_BIT); printf("int = %d 位\n", (int)(sizeof(int) * CHAR_BIT)); printf("INT_MAX = %d\n", INT_MAX); printf("long = %d 位\n", (int)(sizeof(long) * CHAR_BIT)); return 0; } CHAR_BIT = 8 int = 32 位 INT_MAX = 2147483647 long = 32 位

这段输出来自 64 位 Windows（LLP64）：long 仍是 32 位。在 64 位 Linux 上会是 64 位。所以“用 long 存指针”这类写法从一开始就不可移植。

5.2stdint.h：把位宽写进类型名

类型族例子保证什么时候用
精确宽度int8_t uint16_t int32_t恰好这么多位，无填充寄存器、协议字段、二进制文件

标准怎么说

int8_t 这类精确宽度类型是可选的：只有平台确实存在 8 位、无填充、二进制补码的整数类型时才定义。绝大多数平台都有，但写可移植代码时不要假设 int64_t 一定存在（可以用 INT64_MAX 是否存在来判断）。

5.3整数提升与符号扩展

比 int 窄的类型参与运算时，会先被提升为 int。如果原类型是有符号的，提升时做符号扩展：高位补符号位。

动手看

8 位值扩展成 32 位

输入一个 8 位十六进制值，对比“按有符号扩展”和“按无符号零扩展”的结果。

这正是 int8_t 与 uint8_t 在表达式里表现不同的根源。

5.4移位的四条规则

uint32_t u = 1u; u << 31; /* 合法：无符号左移，按 2^32 取模 */ u << 32; /* 未定义行为：移位位数 >= 类型宽度 */ int32_t s = -1; s << 1; /* 未定义行为：左移负数 */ s >> 1; /* 实现定义：可能是算术右移（-1），也可能是逻辑右移 */ uint32_t x = 0x80000000u; x >> 1; /* 合法：逻辑右移，得到 0x40000000 */
工程习惯

需要“算术右移”时，不要依赖 >> 对有符号数的行为。可以显式写：(x >> n) | (~((x >> n) | ~(x >> n)) ...)——太绕了。更实际的做法是：确认目标编译器的行为并写进移植说明，或者先把有符号数转成无符号处理位模式。

5.5字节序：内存里的顺序

一个 32 位整数 0x12345678 在内存里可以有两种排法：

小端

低字节在前

78 56 34 12。x86、大多数 ARM（可配置）、RISC-V 默认小端。

大端

高字节在前

12 34 56 78。部分网络协议、某些 DSP 和 PowerPC 使用大端。

#include #include uint32_t swap32(uint32_t v) { return ((v & 0x000000FFu) << 24) | ((v & 0x0000FF00u) << 8) | ((v & 0x00FF0000u) >> 8) | ((v & 0xFF000000u) >> 24); } int main(void) { uint32_t v = 0x12345678u; printf("%08X -> %08X\n", v, swap32(v)); return 0; } 12345678 -> 78563412
易错

把 uint8_t buf[4] 直接用 memcpy 到 uint32_t，得到的值取决于本机字节序。协议里规定“大端传输”时，必须显式按字节组装，不能依赖 memcpy。

#include /* 从大端字节流读取 32 位，与主机字节序无关 */ uint32_t read_be32(const uint8_t *p) { return ((uint32_t)p[0] << 24) | ((uint32_t)p[1] << 16) | ((uint32_t)p[2] << 8) | ((uint32_t)p[3]); }

5.6三个真实踩过的坑

#include /* 坑 1：两个 uint8_t 相加，结果是 int，不是 uint8_t */ uint8_t a = 200, b = 100; uint8_t c = a + b; /* 300 截断成 44 */ /* 坑 2：char 是否有符号由实现决定 */ char ch = 0xFF; int v = ch; /* 可能是 255，也可能是 -1 */ /* 坑 3：有符号与无符号比较 */ int32_t i = -1; uint32_t u = 1; if (i < u) { } /* 假：i 被转成 4294967295 */
正确做法

处理字节数据一律用 uint8_t；需要字符语义时用 char，但不要假设它的符号性；比较前统一类型，或显式转换并确认范围。

参考答案与思路

1. return (uint32_t)p[0] | ((uint32_t)p[1] << 8) | ((uint32_t)p[2] << 16) | ((uint32_t)p[3] << 24);。

2. uint8_t 时是 128；int8_t 时是 -128（符号扩展）。

3. 1 是 int，左移 31 位会进入符号位，标准规定有符号左移溢出是未定义行为；1u 是无符号，按模运算，合法。

4. uint16_t v = 1; uint8_t *p = (uint8_t *)&v; if (p[0] == 1) 小端;。注意这依赖对象的字节表示，属于实现定义但所有主流平台都成立。

自测：uint8_t a = 0xFF; int b = a;，b 的值是？

uint8_t 是无符号，提升为 int 时做零扩展，得到 255。如果类型是 int8_t，则做符号扩展，得到 -1。

本讲小结

  • 基础类型的宽度由实现决定，跨平台用 stdint.h。
  • 窄类型运算前会提升为 int，有符号做符号扩展、无符号做零扩展。
  • 移位只用无符号类型，移位数必须小于类型宽度。
  • 字节序必须显式处理，不能靠 memcpy 猜。
  • char 的符号性由实现决定，不要依赖。
