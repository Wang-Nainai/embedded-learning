7.1指针复习：这次关注“指向什么”

第 1 册讲过：指针存地址，类型决定步长和解引用宽度。到了嵌入式，指针多了一个新任务——指向代码。函数在内存里也有地址，也可以被指针指向。

#include int add(int a, int b) { return a + b; } int sub(int a, int b) { return a - b; } int main(void) { int (*op)(int, int) = add; /* 函数指针：参数和返回值必须匹配 */ printf("%d\n", op(3, 4)); /* 7 */ op = sub; /* 指向另一个函数 */ printf("%d\n", op(3, 4)); /* -1 */ printf("%d\n", (*op)(3, 4)); /* 也可以显式解引用，等价 */ return 0; } 7 -1 -1
标准怎么说

函数名在表达式中会转换成“指向函数的指针”（除 sizeof 和 & 外）。所以 op = add 和 op = &add 等价，op(3,4) 和 (*op)(3,4) 也等价。两种写法都对，选一种统一即可。

7.2typedef 是函数指针的救命稻草

#ifndef CALLBACK_H #define CALLBACK_H #include /* 事件类型 */ typedef enum { UART_EV_RX_READY, UART_EV_TX_DONE, UART_EV_ERROR } uart_event_t; /* 回调签名：事件 + 用户上下文指针 */ typedef void (*uart_cb_t)(uart_event_t ev, void *ctx); typedef struct { uart_cb_t on_event; void *ctx; } uart_listener_t; void uart_subscribe(uart_listener_t *l); #endif #include "callback.h" static uart_listener_t *g_listener; void uart_subscribe(uart_listener_t *l) { g_listener = l; } /* 中断或驱动内部调用 */ static void uart_emit(uart_event_t ev) { if (g_listener != NULL && g_listener->on_event != NULL) { g_listener->on_event(ev, g_listener->ctx); } }
工程习惯

void *ctx 是回调设计的标准套路：它让同一个回调函数可以服务多个实例。回调里第一件事通常是把 ctx 转回具体类型：my_dev_t *dev = ctx;。没有它，你就得为每个实例写一个回调。

7.3函数指针表：把 if-else 变成查表

#include #include typedef int (*cmd_fn)(int argc, char **argv); static int cmd_help(int argc, char **argv) { (void)argc; (void)argv; printf("help\n"); return 0; } static int cmd_reset(int argc, char **argv) { (void)argc; (void)argv; printf("reset\n"); return 0; } typedef struct { const char *name; cmd_fn fn; const char *help; } command_t; static const command_t g_cmds[] = { {"help", cmd_help, "显示帮助"}, {"reset", cmd_reset, "重启设备"}, }; int main(void) { const char *input = "reset"; for (size_t i = 0; i < sizeof g_cmds / sizeof g_cmds[0]; i++) { if (strcmp(input, g_cmds[i].name) == 0) { return g_cmds[i].fn(0, NULL); } } printf("unknown command\n"); return 1; } reset

命令表的三个好处：新增命令只加一行、不会忘记更新分支、可以自动生成帮助信息。代价是每个命令都要有相同的签名，参数解析要统一。

7.4不透明指针：把实现藏起来

#ifndef SENSOR_H #define SENSOR_H #include /* 只声明，不定义：调用者无法知道结构体里有什么 */ typedef struct sensor sensor_t; sensor_t *sensor_create(uint8_t bus, uint8_t addr); void sensor_destroy(sensor_t *s); int sensor_read(sensor_t *s, int32_t *out); #endif #include "sensor.h" #include struct sensor { uint8_t bus; uint8_t addr; int32_t last; }; sensor_t *sensor_create(uint8_t bus, uint8_t addr) { sensor_t *s = malloc(sizeof *s); if (s == NULL) { return NULL; } s->bus = bus; s->addr = addr; s->last = 0; return s; } void sensor_destroy(sensor_t *s) { free(s); } int sensor_read(sensor_t *s, int32_t *out) { if (s == NULL || out == NULL) { return -1; } *out = s->last; /* 真实实现会去读硬件 */ return 0; }

这种设计叫不透明指针（opaque pointer）。调用者只能通过 sensor_* 函数操作对象，无法直接改字段。好处是：实现可以随时改，ABI 稳定；坏处是多了一次堆分配，且调用者必须记得 destroy。

工程习惯

资源受限时，可以用“静态对象池 + 句柄”替代 malloc：sensor_create 从固定数组里取一个槽位，返回索引或指针。这样既有封装，又不依赖堆。

7.5签名不匹配：编译器不一定救你

void my_cb(int code); /* 只有一个参数 */ /* 期望 void (*)(uart_event_t, void *) */ uart_listener_t l = { (uart_cb_t)my_cb, NULL }; /* 强制转换：编译器闭嘴了 */

强制转换函数指针可以绕过类型检查，但调用时的参数传递方式由真实签名决定。参数个数或类型不一致，行为未定义——在 x86 上可能“碰巧能跑”，在 ARM 上可能直接跑飞。

易错

不要把函数指针转成 void * 再转回来。ISO C 不保证函数指针能放进对象指针；POSIX 才要求两者大小相同。需要泛型回调时，用 void (*)(void *) 这种明确的签名，而不是硬转。

7.6回调的三个工程问题

问题场景对策
悬空回调注册回调的对象已销毁，驱动仍持有函数指针销毁前注销；驱动侧保存 ctx 并校验有效性
上下文错误在中断里调用会阻塞的回调文档写明回调运行在哪个上下文；中断里只置标志
重入回调里又调用了会触发同一回调的 API明确是否可重入；必要时加状态标志或队列

这三条比语法更重要。函数指针本身很简单，难的是约定：谁在什么上下文、什么时候调用、能不能阻塞、对象活多久。

动手练习 · 第 7 讲
  1. 写一个 typedef，表示“接受两个 int、返回 int”的函数指针，并用它实现加减乘除四则运算表。
  2. 给回调加上 ctx 参数，让同一个回调服务两个不同的设备实例。
  3. 解释不透明指针为什么能让 ABI 更稳定。
  4. 为什么中断上下文里不应该调用可能阻塞的回调？
参考答案与思路

1. typedef int (*binop)(int, int);，然后 static const struct { const char *name; binop fn; } table[] = {...};。

2. 回调签名加 void *ctx，注册时把设备指针存进 listener.ctx，回调内部转回具体类型。

3. 调用者只依赖函数签名，不依赖结构体大小和布局；实现内部增删字段不会导致调用者重新编译。

4. 中断上下文不能被阻塞，也不能等待调度；阻塞会导致中断响应延迟，甚至死锁。

自测：int (*op)(int, int) 中，op 是什么？

读法是“从名字往外读”：(*op) 说明 op 是指针，右边 (int,int) 是参数，左边 int 是返回类型。用 typedef int (*binop)(int,int); 会清楚得多。

本讲小结

  • 函数指针让 C 能在运行时选择行为：回调、命令表、状态机表。
  • typedef 能显著提高可读性。
  • 回调要带 void *ctx，并明确上下文与生命周期。
  • 不透明指针隐藏实现、稳定 ABI，代价是分配与销毁。
  • 签名不匹配的强制转换是未定义行为，别做。
