A.2位运算速查

目的表达式说明
2 的幂判断x != 0 && (x & (x-1)) == 00 不是 2 的幂
最低位的 1x & (~x + 1u)等价于 x & -x（无符号）
清除最低位的 1x & (x - 1u)循环计数常用
统计 1 的个数循环 x &= x-1或用 __builtin_popcount
掩码生成((1u << w) - 1u) << posw 为字段宽度
大小端交换 32 位__builtin_bswap32(x)GCC/Clang 扩展
向上对齐(x + a - 1) & ~(a - 1)a 必须是 2 的幂

A.3对齐与结构体速查

规则内容
成员偏移必须是该成员对齐值的整数倍
结构体对齐等于最大成员的对齐值
总大小必须是结构体对齐值的整数倍（末尾补齐）
查偏移offsetof(struct S, member)，需 <stddef.h>
省空间成员按对齐值从大到小排列
紧凑布局__attribute__((packed)) 或 #pragma pack(1)，非标准
验证_Static_assert(offsetof(...) == n, "...")

A.4volatile 检查清单

  • 所有内存映射寄存器指针都加了 volatile
  • 中断与主循环共享的标志加了 volatile
  • 没有把 volatile 当作原子操作或锁
  • 共享计数器的 ++ 有临界区或原子操作保护
  • 多核共享数据使用了屏障或 C11 原子
  • 轮询循环里的读取确实每次都访问内存
  • 没有对 volatile 结构体做整体 memcpy 期望“原子快照”

A.5常见错误对照

现象可能原因排查
轮询永远不退出寄存器指针没有 volatile看反汇编，确认每次循环都有 load
中断里的修改丢失主循环读改写覆盖用 BSRR 或临界区
结构体偏移不对混入小类型导致填充offsetof + 静态断言
换芯片后通信乱码字节序或对齐假设显式按字节序列化
加了 volatile 仍丢数据读改写非原子临界区 / 原子指令
-O2 后行为变了未定义行为UBSan、缩小复现、查有符号溢出
HardFault空指针、越界、非对齐访问看 CFSR/BFAR 与栈帧
RAM 不够大数组/字符串在 .data看 map 文件，改 const 或移出

A.7下一步：从裸机到 RTOS

到这里，你已经能写出“一个主循环 + 中断 + 环形缓冲区”的裸机程序。它能解决很多问题，但也会遇到瓶颈：

  • 多个任务都需要“等待”，主循环只能轮询，响应时间不确定。
  • 阻塞式延时会让其他逻辑全部停摆。
  • 共享资源越来越多，临界区越写越长。

第 3 册会讲 FreeRTOS 如何用任务、优先级、队列、信号量和互斥量来组织这些并发需求。你会发现，本册的环形缓冲区、状态机、临界区，在 RTOS 里都会以新的形式再次出现。
