3.1从位表到掩码

芯片手册的寄存器表通常长这样：

某控制寄存器的位定义（示例）
位名称含义
31:16Reserved保留，写 0
15:8PRESCALER分频系数，0–255
7ENABLE1 = 使能
6:4MODE0 = 关闭，1 = 单次，2 = 连续
3IRQ_EN1 = 允许中断
2:0Reserved保留

把它翻译成 C，只需要三个量：偏移（最低位在哪）、宽度（几位）、掩码（((1u << width) - 1) << offset）。

#include #define CTRL_PRESCALER_POS 8u #define CTRL_PRESCALER_MSK (0xFFu << CTRL_PRESCALER_POS) #define CTRL_ENABLE_POS 7u #define CTRL_ENABLE_MSK (1u << CTRL_ENABLE_POS) #define CTRL_MODE_POS 4u #define CTRL_MODE_MSK (0x7u << CTRL_MODE_POS) #define CTRL_IRQ_POS 3u #define CTRL_IRQ_MSK (1u << CTRL_IRQ_POS)

3.2字段的三个动作：读、写、改

/* 读：先右移对齐，再与掩码 */ static inline uint32_t field_get(uint32_t reg, uint32_t pos, uint32_t msk) { return (reg & msk) >> pos; } /* 写：先清掉字段，再放入新值（调用者保证 value 不超宽） */ static inline uint32_t field_set(uint32_t reg, uint32_t pos, uint32_t msk, uint32_t value) { return (reg & ~msk) | ((value << pos) & msk); } /* 用宏也可以，但内联函数有类型检查，调试也友好 */ #define FIELD_GET(reg, msk, pos) (((reg) & (msk)) >> (pos)) #define FIELD_SET(reg, msk, pos, v) (((reg) & ~(msk)) | (((v) << (pos)) & (msk)))
易错

(value << pos) & msk 里的 & msk 不是可有可无的：如果 value 超出字段宽度，不移除高位就会污染相邻字段。反过来，如果调用者已经保证不超宽，这个与运算也能防止手误。

字段掩码计算器

给定偏移和宽度，看掩码、移位后的值，以及读/写这个字段的完整表达式。

宽度 32 时 (1u << 32) 是未定义行为，需要特判；这里用 64 位中间值演示，实际代码要单独处理。

3.3位域：语法很甜，布局很险

struct Flags { unsigned ready : 1; unsigned mode : 3; unsigned error : 1; unsigned : 3; /* 无名位域：占位，不可访问 */ };

位域能把“几位表示一个字段”写得很直观，但它有几个必须知道的限制：

问题说明
布局由实现定义谁在高位、是否跨存储单元、如何填充，标准都没规定；换编译器/换字节序可能完全不同。
不能取地址&s.ready 非法，因此无法用指针传递单个位域。
类型有限只能用于 int、unsigned、_Bool 或实现允许的类型。
访问仍是读改写写一个位域，编译器通常要读整个存储单元、改位、再写回，仍然不是原子操作。
volatile 位域不同编译器对 volatile 位域的读写次数处理不同，访问硬件寄存器时风险很高。
工程习惯

描述硬件寄存器时，优先用“掩码 + 移位”，不要用位域。位域可以用在纯 RAM 的内部标志上，但也要接受“布局不可移植”这个事实。跨平台协议更是绝对不能用位域直接映射字节流。

3.4四个高频位技巧

#include #include /* 1. 判断是不是 2 的幂（0 不是） */ bool is_pow2(uint32_t x) { return x != 0u && (x & (x - 1u)) == 0u; } /* 2. 统计 1 的个数（Brian Kernighan 法） */ int popcount(uint32_t x) { int n = 0; while (x) { x &= (x - 1u); n++; } return n; } /* 3. 取出最低的 1 及其位置 */ uint32_t lowest_bit(uint32_t x) { return x & (~x + 1u); } /* x & -x */ /* 4. 循环右移（避免负数右移的实现定义行为） */ uint32_t ror(uint32_t x, unsigned n) { n &= 31u; return n ? (x >> n) | (x << (32u - n)) : x; }
标准怎么说

对无符号类型，左移和右移都是良定义的（左移按 2N 取模，右移是逻辑右移）。对有符号负数右移，结果是实现定义；对有符号数左移到符号位，是未定义行为。写底层代码时，位运算一律用无符号类型。

3.5让编译器替你检查位宽

#include #define MODE_MSK (0x7u << 4) /* C11：编译期断言，条件为假直接编译失败 */ _Static_assert((MODE_MSK >> 4) == 0x7u, "MODE 字段宽度必须是 3 位"); _Static_assert(sizeof(uint32_t) == 4, "本文件假设 uint32_t 是 4 字节"); /* C11 之前可用经典技巧 */ typedef char check_mode_width[(MODE_MSK >> 4) == 0x7u ? 1 : -1];

这类断言在寄存器定义、协议常量、缓冲区大小上非常有用：错误在编译期暴露，而不是等到板子跑起来才发现。

动手练习 · 第 3 讲
  1. 为 3.1 节的 MODE 字段写出“设为连续模式（2）”的完整语句，要求不影响其他位。
  2. 写一个函数，把任意 32 位整数的第 i 位到第 j 位反转（i ≤ j）。
  3. 解释 x & (x - 1) 为什么能清除最低位的 1。
  4. 为什么不能用位域直接映射通信协议的字节流？
参考答案与思路

1. CTRL = (CTRL & ~CTRL_MODE_MSK) | (2u << CTRL_MODE_POS);。如果该寄存器支持原子写，优先用硬件机制。

2. 取出字段、逐位反转、再写回；或者用循环把两端位交换。注意 j - i + 1 位宽和移位边界。

3. 减 1 会把最低位的 1 变成 0，并把它右边的所有 0 变成 1；再与原值相与，最低位的 1 及其右侧全部清零，其余位不变。

4. 位域的位序、填充、存储单元大小都由实现决定，不同编译器可能把同一个结构体映射成完全不同的字节序列；协议要求的是精确到 bit 的固定布局。

自测：要把 REG 的 bit5 清零且不影响其他位，正确写法是？

清位要用“与上掩码的取反”：~(1u<<5) 只有 bit5 是 0，其余全是 1，与运算后只清 bit5。B 会把除 bit5 外的所有位清掉；C 会把除 bit5 外的所有位置 1。

本讲小结

  • 字段三要素：偏移、宽度、掩码；写字段要先清后置。
  • 位域布局由实现定义，不适合映射硬件寄存器和协议。
  • 位运算统一用无符号类型，避免未定义/实现定义行为。
  • _Static_assert 能把位宽错误挡在编译期。
