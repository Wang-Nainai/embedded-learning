4.1const：一个承诺，不是一种存储

const 的含义是“通过这个名字不能修改”。它不保证对象真的存放在只读存储器里，也不保证别人不能改。

const int table[4] = {1, 2, 3, 4}; /* table[0] = 9; 编译错误：通过 table 不能改 */ int *p = (int *)table; /* 强制去掉 const：语法上能过 */ /* *p = 9; 未定义行为：修改 const 对象 */ const int n = 10; int arr[n]; /* C99 VLA；不是“常量表达式”，不能用于 case 标签 */
常见说法是否准确更准确的说法
const 变量一定在 Flash / ROM不准确可能被放进 .rodata，也可能被优化成立即数，甚至放在栈上；由实现和链接脚本决定。
const 变量不能改部分准确不能通过这个名字改；通过强制转换后的指针修改是未定义行为。
const 可以用来做数组长度不准确C 里 const int 不是整型常量表达式；用 #define 或 enum。
函数参数加 const 更安全准确它表达“我不会改你的数据”，是接口契约的一部分。
工程习惯

只读查表数据（如字库、CRC 表、字符串）写 const，让链接器有机会放进 Flash，节省宝贵的 SRAM。但不要假设“写了 const 就一定省 RAM”，要看 map 文件确认。

4.2volatile：三保证，三不保证

保证

它确实做的

  • 每次访问都真实发生，不合并、不缓存
  • 不会被优化删除
  • 同一线程内，volatile 访问的相对顺序不被编译器调换
不保证

它做不到的

  • 不保证原子性（32 位写可能分成两次 16 位）
  • 不保证多核/多设备的可见性与顺序（需要屏障或原子类型）
  • 不替代锁，不解决竞态
#include #include /* 1. 内存映射寄存器：必须 volatile */ #define STATUS (*(volatile uint32_t *)0x40001000UL) /* 2. 中断与主循环共享的标志：必须 volatile */ volatile bool g_button_pressed = false; void EXTI_IRQHandler(void) { g_button_pressed = true; /* 中断里写 */ } int main(void) { while (1) { if (g_button_pressed) { /* 主循环读：没有 volatile 可能被优化成只读一次 */ g_button_pressed = false; /* 处理按键 */ } } } /* 3. 只读状态寄存器：const + volatile 组合 */ #define ID_REG (*(const volatile uint32_t *)0x40001FF0UL)
易错

下面这段代码即使加了 volatile 也不安全：

volatile uint32_t counter = 0; counter++; /* 读-改-写三步，中断可能插在中间 */

两个上下文同时执行 counter++，可能各自读到 5，各自写回 6，最终少加一次。正确做法是关中断做临界区，或用硬件原子指令，或使用 C11 _Atomic。

4.3static：一个关键字，三种身份

位置含义典型用途
函数内部的变量静态存储期：只初始化一次，函数返回后仍存在计数器、状态缓存、一次性初始化标志
文件作用域的变量/函数内部链接：其他 .c 文件看不到模块私有实现，避免符号冲突
数组参数中的 staticC99：承诺至少能访问这么多元素给编译器优化提示，日常很少用
static int module_counter; /* 只在本文件可见 */ static void helper(void) { } /* 只在本文件可调用 */ void api_init(void) { static bool inited = false; /* 只初始化一次 */ if (inited) { return; } inited = true; module_counter = 0; }
实现细节

函数内的 static 变量如果没有显式初始化，会被清零，且初始化发生在程序启动前（对嵌入式来说就是启动代码的清零/复制阶段）。它不是线程安全的：多个任务同时第一次调用，可能都看到 inited == false。

4.4extern：声明“别处有定义”

#ifndef MODULE_H #define MODULE_H /* 声明：告诉编译器有这么个变量，但不分配存储 */ extern uint32_t g_sample_count; void module_init(void); #endif #include "module.h" /* 定义：真正分配存储，整个程序只能有一处 */ uint32_t g_sample_count = 0;

常见错误是在头文件里写 uint32_t g_sample_count = 0;：每个包含它的 .c 都会生成一份定义，链接时报 multiple definition。

标准怎么说

在 C 中，文件作用域的 int x; 是暂定定义（tentative definition），同一个翻译单元里可以出现多次，最终合并为一个；但跨翻译单元仍然是多个定义。extern int x; 是纯声明，不分配存储。C++ 的规则不同，不要把 C++ 的 inline 变量习惯带过来。

4.5四个关键字放在一起看

它们各自约束什么
关键字约束对象管得住管不住
const访问权限通过该名字不能写存储位置、别名修改
volatile编译器优化访问不被删除/合并原子性、竞态、跨核顺序
static链接与存储期可见范围、生命周期线程安全、重入
extern声明方式“定义在别处”类型是否真的一致

参考答案与思路

1. 不一定。是否放进 .rodata（Flash）取决于实现和链接脚本；即使放进去，某些情况下也可能有 RAM 副本。用 map 文件确认。

2. 不能。volatile 只阻止优化，不阻止中断在“读”和“写”之间插入，counter++ 仍会丢更新。

3. 在 .c 里定义 static uint32_t s_counter;，只导出 uint32_t counter_get(void)。头文件里不出现变量名。

4. static 函数具有内部链接，符号不出现在目标文件的全局符号表里，不会与其他文件的同名函数冲突；普通函数是外部链接，全程序只能有一个定义。

自测：下面哪个场景必须使用 volatile？

中断会在编译器看不见的时刻改变量，主循环的轮询必须每次真实读内存，否则可能被优化成死循环。mutex 保护的变量需要的是同步语义，不是 volatile；局部变量不存在异步修改。

本讲小结

  • const 是访问权限承诺，不等于“放在 ROM”。
  • volatile 保证访问真实发生，不保证原子性与同步。
  • static 管链接和存储期，不管线程安全。
  • extern 是声明，定义只能有一处。
  • 四个关键字各管一件事，不能互相替代。
