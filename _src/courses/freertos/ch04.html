4.1tick：内核的心跳

FreeRTOS 需要一个周期性的时基来推进延时、超时和时间片。这个时基由硬件定时器（通常是 SysTick）产生，频率由 configTICK_RATE_HZ 决定。

#define configTICK_RATE_HZ 1000 /* 1 kHz：1 tick = 1 ms */

易错

vTaskDelay(100) 的参数是 tick 数，不是毫秒。在 100 Hz 的配置下，它延时 1 秒，不是 100 ms。要么用 pdMS_TO_TICKS(100)，要么在注释里写清楚单位。

/* pdMS_TO_TICKS 按整数除法换算，通常向下取整；小于 1 tick 会变成 0 */ vTaskDelay(pdMS_TO_TICKS(100)); /* 如果编译期就知道 tick 率，也可以直接算，但不要手写魔法数字 */ #define MS_TO_TICKS(ms) ((TickType_t)(((ms) * configTICK_RATE_HZ) / 1000))

4.2相对延时：为什么会漂移

for (;;) { do_work(); /* 假设耗时 3 ms */ vTaskDelay(pdMS_TO_TICKS(10)); /* 再等 10 ms */ }

实际周期不是 10 ms，而是 3 ms + 10 ms = 13 ms，再加上调度延迟。每轮都多出 3 ms，100 轮就偏了 300 ms。这叫累积漂移。

4.3vTaskDelayUntil：固定周期

#include "FreeRTOS.h" #include "task.h" static void sample_task(void *arg) { (void)arg; TickType_t last = xTaskGetTickCount(); const TickType_t period = pdMS_TO_TICKS(10); for (;;) { do_sample(); /* 必须短于 period */ vTaskDelayUntil(&last, period); /* 按绝对时间安排下一次唤醒 */ } }

实现细节

vTaskDelayUntil 不会“追赶”错过的周期。如果某次执行超过 period，下一次会立刻返回，last 仍然按 period 递增，于是任务持续落后。需要检测这种情况（比较当前 tick 与 last），并决定是跳过错过的周期还是报警。

4.4抖动、漂移与精度

  • 抖动：单次唤醒相对理想时刻的偏差，通常由中断延迟、调度延迟、临界区造成。
  • 漂移：长期平均周期偏离目标，通常由相对延时或时钟源误差造成。
  • 分辨率：最小可表达的时间是 1 tick；小于 1 tick 的延时可能被换算成 0，需要自己加 1 或提高 tick 频率。

需要微秒级精度时，不要指望 RTOS 的 tick：用硬件定时器 + 输入捕获/比较，或者用高分辨率定时器做时间戳，RTOS 只负责任务调度。

4.5低功耗：tickless idle

默认配置下，即使没有任务要运行，tick 中断也会每 1 ms 唤醒 CPU。对电池设备，这很浪费。FreeRTOS 提供 tickless 模式（configUSE_TICKLESS_IDLE），在空闲时关闭 tick 中断，直到下一个任务需要唤醒。

工程习惯

tickless 模式需要移植层实现“进入低功耗、按到期时间唤醒”，并且会引入额外的唤醒误差。先用默认模式把功能跑通，再评估功耗优化；不要一上来就开 tickless，否则调试会变复杂。

参考答案与思路

1. 15 × 5 ms = 75 ms（1 tick = 1000/200 = 5 ms）。

2. 初始化 last = xTaskGetTickCount()，循环里 vTaskDelayUntil(&last, pdMS_TO_TICKS(10))。

3. tick 中断本身有响应延迟，任务被唤醒后还要等调度器切换；所以实际间隔 ≥ 1 tick。

4. 下一次会立刻返回（因为目标时刻已过），任务持续落后。可以在循环开头比较 xTaskGetTickCount() - last 与 period，超过就记录一次 overrun。

自测：configTICK_RATE_HZ = 1000，vTaskDelay(50) 大约延时多久？

1 kHz 时 1 tick = 1 ms，所以 50 tick = 50 ms。参数单位是 tick，只有在 1 kHz 配置下才“恰好”等于毫秒。

本讲小结

  • tick 是内核时基，1 tick 不一定等于 1 ms。
  • 相对延时会累积执行时间，导致周期漂移。
  • 周期任务用 vTaskDelayUntil，并按 period 检查 overrun。
  • 抖动来自中断与调度延迟，分辨率受 tick 限制。
  • 微秒级精度要靠硬件定时器，不是 RTOS tick。
