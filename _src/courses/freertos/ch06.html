6.1信号量回答的是“有没有 / 有几个”

信号量不携带数据。它只有一个计数值，任务通过“取”和“给”来同步。二值信号量的值只有 0 和 1，计数信号量可以是 0 到最大值。

二值

事件是否发生

中断发生 → 任务处理。给一次、取一次，之后回到 0。适合“一次性事件通知”。

计数

还剩几个资源 / 发生了几次

初值为 N，取一次减一，给一次加一。适合“缓冲区槽位”“事件累计次数”。

#include "FreeRTOS.h" #include "semphr.h" static SemaphoreHandle_t g_btn_sem; /* 二值 */ static SemaphoreHandle_t g_slot_sem; /* 计数：3 个槽位 */ void app_init(void) { g_btn_sem = xSemaphoreCreateBinary(); g_slot_sem = xSemaphoreCreateCounting(3, 3); configASSERT(g_btn_sem != NULL && g_slot_sem != NULL); } /* 中断：只给信号 */ void EXTI_IRQHandler(void) { BaseType_t woken = pdFALSE; xSemaphoreGiveFromISR(g_btn_sem, &woken); portYIELD_FROM_ISR(woken); } /* 任务：等待事件 */ static void button_task(void *arg) { (void)arg; for (;;) { if (xSemaphoreTake(g_btn_sem, portMAX_DELAY) == pdTRUE) { handle_button(); } } }
易错

二值信号量不计数。中断连续给两次、任务只取一次，第二次“给”会被丢弃（因为值已经是 1）。如果需要累计事件次数，用计数信号量；如果需要保留每一次的数据，用队列。

6.2信号量不是队列

队列二值信号量计数信号量
携带数据是否否
容量N 个元素1N
重复给排队，直到满丢弃（已为 1）累加，直到最大值
典型用途传样本、命令中断→任务同步资源计数、事件累计

如果发现自己“给信号量之后再去读一个全局变量”，那多半应该用队列：把数据一起传过去，避免额外的共享状态。

6.3计数信号量：资源池

/* 3 个缓冲区，用计数信号量表示可用数量 */ static uint8_t g_pool[3][64]; static SemaphoreHandle_t g_free_slots; uint8_t *buf_acquire(TickType_t timeout) { if (xSemaphoreTake(g_free_slots, timeout) != pdTRUE) { return NULL; /* 超时：没有可用缓冲区 */ } /* 这里需要一个“哪个槽位空了”的映射，简化起见用原子索引 */ return next_free_buffer(); } void buf_release(uint8_t *buf) { (void)buf; xSemaphoreGive(g_free_slots); /* 归还一个槽位 */ }
实现细节

上面的简化版有一个坑：信号量只表示“有几个空位”，不表示“哪一个空”。多任务同时获取时，还需要一个受保护的分配索引。更完整的做法是用队列存“空闲缓冲区指针”，取到即独占，用完再放回队列。

6.4什么时候不该用信号量

需求不该用信号量应该用
传递数据二值/计数信号量队列、流缓冲区
保护共享资源二值信号量互斥量（支持优先级继承）
等待多个条件多个信号量轮询事件组
一对一轻量唤醒队列/信号量任务通知（更省）

参考答案与思路

3. 它没有所有者概念，也不支持优先级继承；低优先级任务持有时，高优先级任务只能干等，容易出现优先级反转。

4. 大量事件被合并/丢弃：信号量最多为 1，任务处理不过来时，后续“给”操作无效。应该用计数信号量记录丢失次数，或改用队列并设计丢弃策略。

自测：二值信号量已经被“给”过一次（值为 1），再“给”一次会怎样？

二值信号量最大就是 1，重复给不会累加。要累计次数，用计数信号量；要保留每次事件的数据，用队列。

本讲小结

  • 信号量只传递“事件/计数”，不传递数据。
  • 二值用于一次性同步，计数用于资源或事件累计。
  • 中断里用 FromISR 版本并处理 yield。
  • 保护共享资源用互斥量，不用二值信号量。
  • 需要数据就用队列，不要“信号量 + 全局变量”。
