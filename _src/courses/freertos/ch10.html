10.1一行 C 不是原子操作

g_counter++ 编译后是“读 → 加 → 写”。两个任务交替执行时，可能都读到 5，各自写回 6，最终少加一次。这类问题叫竞争条件（race condition）。

static uint32_t g_counter; void task_a(void *arg) { (void)arg; for (;;) { g_counter++; vTaskDelay(1); } } void task_b(void *arg) { (void)arg; for (;;) { g_counter++; vTaskDelay(1); } }
易错

加 volatile 不能解决竞争。它只保证“每次都去内存读”，不保证“读和写之间不被打断”。竞争需要互斥或原子操作。

10.2临界区：短暂关闭调度与中断

#include "FreeRTOS.h" #include "task.h" void update_counter(void) { taskENTER_CRITICAL(); g_counter++; /* 这期间不会被任务切换或受管中断打断 */ taskEXIT_CRITICAL(); }
API作用范围能否嵌套适用
taskENTER_CRITICAL屏蔽受管中断 + 禁止调度是（计数）几行代码的原子更新
vTaskSuspendAll只禁止任务切换，中断仍运行是较长的只读遍历、避免中断延迟
portENTER_CRITICAL更底层，移植相关视端口内核/驱动内部
实现细节

在 Cortex-M 端口上，taskENTER_CRITICAL() 会把 BASEPRI 设为 configMAX_SYSCALL_INTERRUPT_PRIORITY，从而屏蔽“允许调用 FreeRTOS API 的中断”，但不屏蔽更高优先级的中断。所以临界区并不能防止所有中断修改数据——那些高优先级中断本来就不该碰共享数据。

10.3关中断 vs 挂起调度器

taskENTER_CRITICAL

更“硬”的保护

连中断都挡在外面。适合几行代码的读改写、链表插入。时间必须极短，否则中断延迟变大。

vTaskSuspendAll

只挡任务切换

中断照常运行，所以中断仍可能修改数据。适合“遍历一个不会被中断修改的结构”，或避免长时间关中断。

/* 遍历一个只被任务修改的链表：不需要关中断 */ vTaskSuspendAll(); for (node_t *p = g_list; p != NULL; p = p->next) { inspect(p); } xTaskResumeAll();

10.4可重入与线程安全

概念含义例子
可重入同一函数被多个上下文同时调用仍正确只用参数和局部变量的函数
线程安全多任务调用不会破坏共享状态内部加锁，或使用原子操作
不可重入依赖静态缓冲区/全局状态strtok、部分 printf 实现
/* 不可重入：静态缓冲区被共享 */ char *bad_itoa(int v) { static char buf[12]; snprintf(buf, sizeof buf, "%d", v); return buf; } /* 可重入：由调用者提供缓冲区 */ void good_itoa(int v, char *out, size_t n) { snprintf(out, n, "%d", v); }
工程习惯

标准库的 printf、malloc、strtok 在嵌入式里经常不可重入或实现很重。要么用可重入版本（strtok_r、snprintf 到调用者缓冲区），要么在接口层面约定“只在某个任务里调用”。

10.5临界区该有多长

临界区的长度直接决定最坏中断延迟。经验值：几微秒到几十微秒；超过 100 µs 就要重新设计。

  • 把计算、拷贝、判断尽量移到临界区外。
  • 只保护“必须原子”的那几行。
  • 不要在临界区里调用 printf、malloc、可能阻塞的 API。
  • 用示波器/GPIO 翻转测量临界区时长，不要凭感觉。
gpio_set(DEBUG_PIN); taskENTER_CRITICAL(); /* 被测代码 */ taskEXIT_CRITICAL(); gpio_clear(DEBUG_PIN);

  2. 用 taskENTER_CRITICAL 修复，并说明临界区应该包住哪些行。
  3. 什么时候该用 vTaskSuspendAll 而不是关中断？
  4. 判断 strtok 是否可重入，给出替代方案。
参考答案与思路

1. 通常小于 20000，具体值不确定；两个任务读到相同旧值后互相覆盖。

2. 只包住 g_counter++ 这一行；如果还有“读-判断-写”的逻辑，要一起包住。

3. 遍历一个只被任务修改的结构，且不想拉长中断关闭时间时。

4. 不可重入（内部保存静态状态）。用 strtok_r，或自己写基于指针的切分函数。

自测：临界区里最不应该做的是？

printf 可能阻塞、可能很长，还会调用不可重入的内部函数；放在临界区里会显著拉长中断关闭时间。

本讲小结

  • 竞争条件来自非原子的读改写，volatile 解决不了。
  • 临界区屏蔽受管中断，适合极短的原子操作。
  • vTaskSuspendAll 只禁止任务切换，不挡中断。
  • 可重入函数不依赖共享状态，线程安全靠同步保证。
  • 临界区长度要用测量说话，不能凭感觉。
