5.1队列不是共享变量

队列是一段固定长度的缓冲区，每个元素大小固定。发送时按值复制进去，接收时按值复制出来。它解决的是“有界传递 + 阻塞等待”，不是“共享内存”。

特性含义后果
按值复制发送的是数据的副本发送方可以立刻复用原缓冲区；但大结构体复制开销大
固定长度创建时确定，不能动态扩容满了必须等待或丢弃，策略要显式设计
FIFO默认先进先出也有 xQueueSendToFront 用于插队
线程安全内部已处理临界区不需要额外加锁

5.2创建、发送、接收

#include "FreeRTOS.h" #include "queue.h" typedef struct { uint16_t id; int32_t value; } sample_t; static QueueHandle_t g_samples; void app_init(void) { /* 长度 8，每个元素 sizeof(sample_t) */ g_samples = xQueueCreate(8, sizeof(sample_t)); configASSERT(g_samples != NULL); } /* 生产者任务 */ static void producer(void *arg) { (void)arg; uint16_t id = 0; for (;;) { sample_t s = { .id = id++, .value = read_adc() }; /* 最多等 10 ms；队列满则返回 errQUEUE_FULL */ if (xQueueSend(g_samples, &s, pdMS_TO_TICKS(10)) != pdPASS) { g_drop_count++; /* 丢弃并计数，不要静默 */ } vTaskDelay(pdMS_TO_TICKS(20)); } } /* 消费者任务 */ static void consumer(void *arg) { (void)arg; sample_t s; for (;;) { /* 最多等 100 ms；超时返回 pdFALSE */ if (xQueueReceive(g_samples, &s, pdMS_TO_TICKS(100)) == pdPASS) { process(&s); } else { /* 超时：可以做健康检查、心跳、低功耗 */ } } }
实现细节

队列满时，xQueueSend 会把当前任务放入“等待发送”的阻塞列表；一旦有空间，最高优先级的等待者被唤醒。等待时间以 tick 为单位，0 表示不等待，portMAX_DELAY 表示无限等待（需要 INCLUDE_vTaskSuspend = 1）。

动手看

队列满/空时，返回值是什么

容量 4。连续放入看它变满，连续取出看它变空。注意“满时不是覆盖，空时不是崩溃”。

真实调用还会带超时参数：等待期间任务处于 Blocked，超时后返回 errQUEUE_FULL 或 pdFALSE。

5.3队列长度怎么定

队列长度的本质是“允许积压多少”。它由三个量决定：

生产速率　每秒产生多少元素（突发时可能是平均值的数倍）。
消费速率　每秒处理多少元素，最坏情况下的处理时间。
可容忍延迟　从产生到处理，最多能等多久。

一个粗略公式：长度 ≥ (生产速率 - 消费速率) × 最大阻塞时间。如果生产长期快于消费，队列再大也会满——那不是队列长度问题，是系统过载。

易错

把指针放进队列来“避免复制大结构体”，但指针指向的是发送方的栈或会被复用的缓冲区。接收方拿到指针时，内容可能已经变了。要么复制数据，要么用内存池 + 明确的所有权转移。

5.5队列、邮箱与流缓冲区

FreeRTOS 还有两种“像队列”的东西，容易混：

机制传什么适用
队列固定大小的元素，按值复制结构体、命令、样本
流缓冲区 / 消息缓冲区字节流，可变长度串口数据、连续字节流
任务通知一个 32 位值（或计数）轻量事件、一对一唤醒

流缓冲区适合“字节流”，但它不保留消息边界；需要边界时用消息缓冲区，或者自己在字节流上做帧解析。

自测：队列长度 4、已满，任务调用 xQueueSend(q, &x, 0)，结果是？

超时为 0 表示不等待，队列满时立刻返回失败。要等待就传一个非 0 的 tick 超时；要覆盖旧数据，需要自己先接收再发送，或者改用流缓冲区/环形缓冲。

本讲小结

  • 队列按值复制、长度固定、线程安全。
  • 满/空/超时都必须显式处理，不能假设成功。
  • 队列长度由生产/消费速率与可容忍延迟决定。
  • 中断里只能用 FromISR 版本，并处理 yield。
  • 大对象考虑内存池与所有权，而不是裸指针。
