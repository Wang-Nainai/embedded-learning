12.1五种堆方案

FreeRTOS 把 pvPortMalloc / vPortFree 的实现放在 heap_x.c 里，由你选择其中一个加入工程。

方案能释放吗碎片适用
heap_1不能无只在启动时创建任务/队列，之后不释放
heap_2能不会合并相邻块旧项目；新项目不建议
heap_3能取决于 libc malloc使用编译器自带 malloc，需实现线程安全
heap_4能会合并相邻空闲块通用首选
heap_5能同 heap_4，多区域RAM 不连续（如内部 + 外部 SRAM）
工程习惯

长期运行的设备优先 heap_4（合并碎片）或静态分配（完全不依赖堆）。heap_2 不合并相邻空闲块，反复分配/释放后很容易“总量够但最大块不够”。

12.2堆有多大，谁在用

#include "FreeRTOS.h" #include "task.h" void report_heap(void) { size_t free_now = xPortGetFreeHeapSize(); size_t min_ever = xPortGetMinimumEverFreeHeapSize(); /* 需要 heap_4/5 */ printf("heap free=%u, min ever=%u\n", (unsigned)free_now, (unsigned)min_ever); }

configTOTAL_HEAP_SIZE 是堆的总大小。任务栈、TCB、队列、信号量、事件组、定时器都从这里分配（动态创建时）。

实现细节

xPortGetMinimumEverFreeHeapSize 只有 heap_4 和 heap_5 提供。它记录历史最低空闲量，是判断“堆是否够用”的关键指标——当前空闲很多，不代表高峰时没接近耗尽。

12.3任务栈：每个任务都在花 RAM

任务栈要容纳：局部变量、函数调用返回地址、保存的寄存器、中断嵌套时的上下文。栈太小会踩坏相邻内存，表现为“变量莫名其妙变了”或 HardFault。

/* 需要 configUSE_TRACE_FACILITY = 1 或 INCLUDE_uxTaskGetStackHighWaterMark = 1 */ UBaseType_t hw = uxTaskGetStackHighWaterMark(g_worker); /* hw 是“历史最小剩余量”，单位是字。越小越危险。 */ if (hw < 32) { /* 余量不足 32 字（Cortex-M 上 128 字节），应该增大栈 */ }

12.4栈大小怎么估

先给足　按经验给一个偏大的值（例如 256–512 字），先让功能跑起来。
测高水位　跑遍所有分支、最坏输入、中断嵌套场景，读 uxTaskGetStackHighWaterMark。
留余量　保留至少 25%–30% 余量，再把栈调小；不要压到“刚好不溢出”。
回归　每次加功能后重新测，尤其是增加了深层调用或大局部数组。
易错

只在“正常路径”测高水位是不够的。错误处理、异常输入、通信断开重连这些路径往往调用更深、局部变量更多，才是栈的真正峰值。

12.5碎片：为什么“总量够却分配失败”

假设堆里有 3 个 100 字节的空闲块，但你要分配 250 字节——总量 300 够，却没有连续的 250 字节。这就是外部碎片。

  • heap_4 会合并相邻空闲块，能缓解但不能消除碎片。
  • 反复创建/删除不同大小的任务和队列，最容易产生碎片。
  • 长期运行的系统，优先“启动时一次性分配，运行期不再分配”。
正确做法

把 xPortGetMinimumEverFreeHeapSize 和分配失败计数一起上报。如果最小值持续下降，说明有泄漏；如果最小值稳定但分配仍失败，说明碎片严重。

动手练习 · 第 12 讲
  1. 一个任务栈设为 256 字，Cortex-M 上占多少字节？
  2. 高水位显示 8 字，说明什么？该怎么办？
  3. heap_1 和 heap_4 的核心区别是什么？各自适合什么项目？
  4. 为什么“启动时分配、运行期不分配”能显著降低碎片风险？
参考答案与思路

1. 256 × 4 = 1024 字节，另加 TCB。

2. 历史最小剩余只有 8 字（32 字节），几乎贴底，随时可能溢出；应立即增大栈并检查是否有大局部数组/深调用。

3. heap_1 只能分配不能释放，完全没有碎片，适合“启动后固定”的系统；heap_4 可分配可释放并合并相邻块，适合需要动态创建/删除的场景。

4. 碎片来自“不同大小块的反复分配释放”；如果所有块在启动时一次性分配、大小固定，运行期不再切割堆，就不会产生外部碎片。

自测：uxTaskGetStackHighWaterMark 返回 20，含义是？

它返回的是“从任务启动到现在，栈最多被用到离栈底还剩多少”，单位是字。数值越小越危险，不是越大越危险。

本讲小结

  • heap_1 不可释放，heap_4 通用，heap_5 支持多区域。
  • 堆的总量、历史最低空闲量都要监控。
  • 栈深度单位是字，栈溢出往往表现为“莫名其妙的数据损坏”。
  • 高水位要在最坏路径上测，并留 25% 以上余量。
  • 长期运行系统尽量在启动时完成分配。
