2.1任务函数的形状

#include "FreeRTOS.h" #include "task.h" static void my_task(void *arg) { /* 初始化：只在任务第一次运行时执行 */ int *config = (int *)arg; for (;;) { /* 循环体：任务的主体 */ vTaskDelay(pdMS_TO_TICKS(100)); } /* 永远不要执行到这里 */ vTaskDelete(NULL); }

三个硬性要求：

签名固定　void (*)(void *)，参数是一个 void *，返回值是 void。
不能返回　返回意味着任务函数退出，但任务没有“调用者”可以返回。必须死循环，或者显式 vTaskDelete(NULL)。
栈上别放大对象　任务栈通常只有几百字节到几 KB，大数组请用静态分配或堆。

2.2xTaskCreate 的六个参数

BaseType_t xTaskCreate( TaskFunction_t pxTaskCode, /* 任务函数 */ const char * const pcName, /* 名字，仅用于调试 */ configSTACK_DEPTH_TYPE usStackDepth,/* 栈深度，单位是“字” */ void * const pvParameters, /* 传给任务的参数 */ UBaseType_t uxPriority, /* 优先级，数字越大越高 */ TaskHandle_t * const pxCreatedTask /* 返回句柄，可为 NULL */ );
参数注意点
usStackDepth单位是 StackType_t 的个数，不是字节。Cortex-M 上 StackType_t 是 uint32_t，所以 128 表示 512 字节。
pvParameters只是把指针存起来，不会复制所指对象。传局部变量地址会在任务启动前失效。
uxPriority范围 0 到 configMAX_PRIORITIES - 1；数值越大优先级越高。
返回值pdPASS 成功；errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY 表示堆不够。
易错

“栈深度 128”被理解成 128 字节，是最常见的误解之一。实际字节数 = usStackDepth * sizeof(StackType_t)。在 Cortex-M 上是 4 倍关系，在 8 位 AVR 上是 1 倍，在 16 位 MSP430 上是 2 倍。

2.3创建、检查、再使用

#include "FreeRTOS.h" #include "task.h" #define TASK_STACK_WORDS 256 /* 1024 字节（Cortex-M） */ #define TASK_PRIO 3 static TaskHandle_t g_worker; void app_start(void) { BaseType_t ok = xTaskCreate(worker_task, "worker", TASK_STACK_WORDS, NULL, TASK_PRIO, &g_worker); if (ok != pdPASS) { /* 不要静默继续：记录错误、点亮故障灯、复位 */ fatal_error(ERR_TASK_CREATE); } }

句柄的用途：删除任务、改变优先级、给任务发通知、查询状态。如果不需要，传 NULL 即可。

2.4静态创建：不用堆

#include "FreeRTOS.h" #include "task.h" static StaticTask_t g_task_buf; static StackType_t g_task_stack[256]; void app_start_static(void) { TaskHandle_t h = xTaskCreateStatic(worker_task, "worker", 256, NULL, 3, g_task_stack, &g_task_buf); configASSERT(h != NULL); }

静态创建要求 configSUPPORT_STATIC_ALLOCATION = 1，并且需要自己提供空闲任务和定时器任务的内存（如果启用）。好处是链接期就能确定 RAM 占用，没有堆分配失败的风险。

工程习惯

安全关键或长期运行的设备，优先静态创建：内存占用可预测，不会因为碎片在运行几个月后突然创建失败。原型阶段用动态创建更方便，量产前再评估是否切换。

2.5删除任务

/* 任务删除自己：传入 NULL */ vTaskDelete(NULL); /* 删除别的任务：需要句柄 */ if (g_worker != NULL) { vTaskDelete(g_worker); g_worker = NULL; }
实现细节

删除任务时，它占用的栈和 TCB 不会立刻释放，而是由空闲任务回收。如果程序不停地创建和删除任务，而空闲任务得不到运行机会，内存就会持续减少。这是“动态创建任务”最常见的隐性泄漏。

2.6四个典型错误

错误现象修正
任务函数返回HardFault 或行为异常死循环，或返回前 vTaskDelete(NULL)
栈太小偶发崩溃、变量被改增大栈，开栈溢出检测，看高水位
传局部变量地址任务读到随机值传静态/全局变量，或把值放进结构体
优先级超出范围创建失败或被截断检查 configMAX_PRIORITIES

自测：Cortex-M 上 xTaskCreate(..., 128, ...) 的栈大约是多少字节？

栈深度单位是 StackType_t 的个数。Cortex-M 上它是 32 位，所以 128 × 4 = 512 字节。

本讲小结

  • 任务函数签名固定、不能返回、必须有死循环或自删除。
  • 栈深度单位是“字”，不是字节。
  • 参数只传指针，不复制对象，注意生命周期。
  • 创建失败必须处理，不能假设一定成功。
  • 静态创建内存可预测，适合量产与安全关键场景。
