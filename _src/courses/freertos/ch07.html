7.1互斥量不是“二值信号量换名字”

二值信号量互斥量（mutex）
所有者无有：谁取到，谁负责给
优先级继承不支持支持（可配置）
中断中使用可以（FromISR 给）不可以
递归获取不支持可用递归互斥量
典型用途事件通知保护共享资源
#include "FreeRTOS.h" #include "semphr.h" static SemaphoreHandle_t g_i2c_mutex; void app_init(void) { g_i2c_mutex = xSemaphoreCreateMutex(); configASSERT(g_i2c_mutex != NULL); } int read_sensor(uint8_t addr, uint8_t *out, size_t n) { if (xSemaphoreTake(g_i2c_mutex, pdMS_TO_TICKS(50)) != pdTRUE) { return -1; /* 等不到锁：返回错误，不要死等 */ } int ret = i2c_transfer(addr, out, n); xSemaphoreGive(g_i2c_mutex); /* 必须由持有者释放 */ return ret; }
易错

在中断里调用 xSemaphoreTake 取互斥量是未定义行为：中断没有任务上下文，也不存在“所有者”。中断要保护数据，用临界区；要通知任务，用 FromISR 的信号量或队列。

7.2优先级反转：高优先级被低优先级“拖住”

场景：低优先级任务 L 持有互斥量，高优先级任务 H 需要同一把锁，于是 H 阻塞。此时中优先级任务 M 就绪——M 的优先级高于 L，于是 M 抢占 L，L 无法继续执行，也就无法释放锁。结果：H 在等 M 跑完。

动手看

三种优先级，一次反转

切换“无继承 / 有继承”，单步看 CPU 被谁占用，以及 L 的优先级如何变化。

现实中反转往往表现为“偶尔卡顿几百毫秒”，很难复现；一旦出现，先查持锁任务是否被中优先级任务抢占。

7.3死锁：互相等对方的锁

/* 任务 A */ xSemaphoreTake(m1, portMAX_DELAY); xSemaphoreTake(m2, portMAX_DELAY); /* 等 B 释放 m2 */ /* 任务 B */ xSemaphoreTake(m2, portMAX_DELAY); xSemaphoreTake(m1, portMAX_DELAY); /* 等 A 释放 m1 */

死锁需要四个条件同时成立：互斥、持有并等待、不可剥夺、循环等待。破坏任意一个就能避免：

条件怎么破坏
循环等待全局约定加锁顺序（例如永远先 m1 后 m2）
持有并等待一次性申请所有锁，或申请失败就释放已持有的
不可剥夺用带超时的 xSemaphoreTake，超时后释放重试
互斥尽量用无锁设计（单生产者单消费者队列）
工程习惯

带超时的加锁不是“万能解”，但它能把“永久卡死”变成“可恢复的错误”。超时后要记录日志、释放已持有的锁、按退避策略重试，否则只是换一种方式失败。

7.4递归互斥量

static SemaphoreHandle_t g_lock; void init(void) { g_lock = xSemaphoreCreateRecursiveMutex(); } void outer(void) { xSemaphoreTakeRecursive(g_lock, portMAX_DELAY); inner(); /* inner 里还会再取一次 */ xSemaphoreGiveRecursive(g_lock); } void inner(void) { xSemaphoreTakeRecursive(g_lock, portMAX_DELAY); /* ... */ xSemaphoreGiveRecursive(g_lock); }

普通互斥量在同一任务里重复获取会死锁（任务等自己释放）。递归互斥量用计数解决这个问题，但获取和释放必须成对，且不能跨任务使用。

参考答案与思路

2. 继承只提升持锁者的优先级，让它可以尽快运行；但死锁是“双方都在等对方释放”，提升优先级也不会让任何一方释放。

3. 统一加锁顺序（都先 A 后 B），或者用一次性申请/超时回退。

4. 一个公共函数可能被“已经持锁”的调用者再次调用，例如日志模块的 log_write 内部又调用了 log_flush，两者都加同一把锁。

自测：优先级继承的作用是？

继承只提升“持锁者”的优先级，缩短高优先级任务的间接阻塞时间；它不消除阻塞，也不防止死锁。

本讲小结

  • 互斥量有所有者、支持优先级继承、不能在 ISR 使用。
  • 优先级反转：中优先级任务间接阻塞高优先级任务。
  • 继承缓解反转，但不解决死锁与长临界区。
  • 死锁靠加锁顺序、超时与无锁设计来避免。
  • 递归互斥量解决同任务重复加锁，但必须成对。
